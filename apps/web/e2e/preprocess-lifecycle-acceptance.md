# Preprocessing lifecycle browser acceptance

Date: 2026-09-15. Branch: `fix/frontend-polish`, HEAD `d4b722a1` plus the uncommitted lifecycle consolidation. Result: **5 scenarios, each repeated twice; 10 passed, 0 failed, 0 skipped, 0 flaky retries**. No production changes were required during browser acceptance.

## Harness and isolation

[The spec](./preprocess-lifecycle.spec.ts) uses real Chromium UI interactions, the actual frontend/store/queues, and real Disk-backed topology and content persistence. It reuses `openNewCanvas()` and the existing clipboard fixture pattern. [The configuration](../playwright.preprocess-lifecycle.config.ts) reuses the portal acceptance harness's credential-free services, temporary workspace/data/HOME, explicit Huabu working directories, and teardown. Ports are 3197/5297 with `reuseExistingServer: false`; the other worktree's 5294 service was not used. Browser requests to remote origins and POST requests for agent execution are forbidden; read-only chat metadata is allowed.

No store imports, direct store mutations, or lifecycle calls are injected into the browser. Initial Notes are created with the existing browser ClipboardEvent fixture; editing, preview-tab close, Text placement/blur, node drag/delete, undo/redo, and reload use actual UI. Persistence is verified by HTTP readback and, where indicated, page reload. Controlled preprocessing responses are synthetic successes with identifiable suggested labels; held restored-content PUTs are released to the real server without modifying their body or response. The Text scenario does not mock preprocessing. Credentials are absent, so this does not validate remote LLM enrichment.

## Validation and limits

The final repeated run completed in 2.4 minutes. The new spec and configuration pass ESLint, Prettier, standalone TypeScript checking, and editor diagnostics. The earlier production validation remains 169 Web test files / 1235 tests passed, with repository typecheck and format passing; this browser-only addition does not change production code.

The first harness run failed because it used an obsolete exact `Close` selector and blocked read-only agent metadata. The observed page exposed `Close <label>` inside the selected preview tab; correcting those two harness errors yielded four passing scenarios, followed by the final five-scenario repeated run. These initial failures are not attributed to product code.

This is targeted desktop Chromium acceptance, not exhaustive browser/device coverage. Retry after failed restored persistence, protected manual rename, Canvas switching, Frame-child input changes, and the exact adjacent-history B-to-B stale-input case remain covered at unit/integration level rather than separately demonstrated here. Server-side late derived-content writes, real remote extraction/enrichment, and all possible interleavings are not certified by client response gates. No commit or push was performed.
