# Huabu Desktop Threat Model

## Scope

This model covers the installed desktop app hosting its bundled Huabu Server, the desktop UI, and external Agents attached to that Server through Agentlet. An Agent may execute on the desktop's own device or on another connected device; its execution location does not exclude it from the Agent trust and reachback considerations below.

The bundled Server binds to loopback by default. An Agent on another device needs a configured connection path; this model does not claim that loopback makes an externally exposed or forwarded endpoint safe. Network exposure and transport protection must be assessed for that connection path. Using the desktop solely as a client of a separately deployed Huabu Server is outside this model.

Every control under [Implemented controls](#implemented-controls) is in the code at the path given beside it. Hardening that is not in the code is listed separately under [Not implemented](#not-implemented) and is not relied on.

## Trust assumptions

Users select and authorize their own external Agents. These Agents run with the operating-system privileges of their account on the execution device; Huabu does not provide an additional OS-level execution sandbox. Execution isolation and the Agent's own command-approval policy depend on the selected provider and user configuration.

Huabu removes inherited `HUABU_*` configuration when starting its Server-owned local Agentlet and explicitly injects the runtime coordinates and credentials an Agent needs. Agents on connected devices use those devices' environments rather than inheriting the desktop Server's environment. Other inherited environment variables remain available for the user's Agent authentication and toolchain. This is not an allowlist of all possible environment variables or a guarantee that inherited user configuration contains no secrets.

## Architecture and data flows

```mermaid
flowchart LR
  USER[Desktop user]
  LOCAL[Other local process]
  WEB[Untrusted web content]
  CLOUD[AI and integration services]
  UPDATE[Update repository]

  subgraph APP[Trust boundary: Huabu desktop]
    subgraph SANDBOX[Trust boundary: Chromium sandbox]
      UI[Renderer UI]
      FRAME[Web preview]
    end
    MAIN[Electron main process]
    SERVER[Bundled local service]
  end

  subgraph AGENTDEVICE[Trust boundary: Agent execution device]
    AGENT[External Agent process on local or connected device]
  end

  subgraph DEVICE[Trust boundary: user device storage]
    SPACE[Workspace data]
    VAULT[OS-protected credential vault]
  end

  USER -->|Input and consent| UI
  UI <-->|Restricted IPC| MAIN
  UI <-->|HTTP and SSE on 127.0.0.1 with launch token| SERVER
  LOCAL -.->|Loopback requests refused without token| SERVER
  WEB -->|Active framed content| FRAME
  SERVER <-->|Prompts content and responses over HTTPS| CLOUD
  MAIN <-->|Update metadata and packages| UPDATE
  MAIN <-->|Encrypted credential operations| VAULT
  MAIN -->|Credential snapshot over process IPC and launch token| SERVER
  SERVER <-->|Read and write| SPACE
  SERVER -->|Spawn with machine reachback token| AGENT
  AGENT -->|Bearer-authenticated Space operations| SERVER
```

## Not implemented

These are known gaps. None is counted as a mitigation above.

| Threat                                    | Gap                                                                                                                                                                                | Status                          |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- |
| Prompt injection and unsafe Agent actions | Task-specific permissions for Huabu tools are not enforced. Reference-content labeling and command validation do not restrict an Agent to the capabilities required by one task.   | Not implemented; not scheduled. |
| External Agent token theft                | In local desktop mode, the reachback token grants access to every Space and does not expire. Per-Space, permission-limited, short-lived reachback credentials are not implemented. | Not implemented; not scheduled. |

## Sensitive assets

- Workspace content, artifacts, memory, history, and settings.
- LLM, integration, and OAuth credentials.
- Agent instructions, responses, tools, and reachback bearer tokens.
- Desktop packages, update metadata, logs, and crash diagnostics.

## Entra permissions

The reviewed desktop application does not request Microsoft Entra tenant permissions or Microsoft Graph permissions. If such permissions are introduced, the exact delegated or application permissions, accessed data, consent requirements, and token flow must be added to this model before tenant review.
