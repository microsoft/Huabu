# Sketch Node

> Sketch node (`type: 'sketch'`): freehand strokes as a persistent canvas node.
> A sketch shares the same lifecycle as every other node (create, move, delete,
> nest in a frame, recolor, relabel) and does NOT disappear after being read by
> AI.

A sketch relates to AI in exactly one way (§4): **as a content node**. Like an
image, it carries visual information; agents render it to a PNG via
`snapshot_node` to "see" it and fold it into their understanding of the Space.
No explicit trigger is needed.

> Sketches used to have a second, user-triggered relationship — `✨ Apply Sketch`
> parsed strokes into `CanvasCommand[]`. That gesture-recognition pipeline was
> removed together with the intent recogniser; a sketch is now purely content.

§1–§3 are the basics (goals, data model, lifecycle); §5 is the code index.

| Goal            | Why                                                                     |
| --------------- | ----------------------------------------------------------------------- |
| Ordinary node   | Lifecycle owned by the user; AI reading never auto-deletes the node     |
| Content-bearing | Strokes carry visual info; agents snapshot to PNG and use it as context |

## 3. Node lifecycle

Drawing lands a normal node; no Agent request fires automatically:

```
SketchOverlay.handlePointerUp
   │
   ▼
addNode({type: 'sketch', ...})
```

- Ordinary finished sketches trigger no interpretation or dispatch. Handwritten `#` detection is always enabled while drawing: a local four-stroke check after a 400 ms quiet window may open a resource picker (§4.2), but does not invoke an Agent.
- Move / delete / recolor / nest-in-frame / relabel all go through the normal node flow.

### 3.1 Draw does not auto-select

A freshly drawn sketch is created **unselected**: `SketchOverlay` passes `selectOnCreate: false` on `addNode`, which threads through `ADD_NODES` → `CREATE_NODES` so the engine's [createNodes.ts](../../packages/shared/src/canvas-engine/commands/createNodes.ts) skips it in the auto-selection set. Two independent guards suppress create-time selection — the type-invariant `question` exclusion and the per-creation `selectOnCreate === false` hint — do not collapse them. Rationale: a selection box mid-draw interrupts continuous freehand writing, and an unselected sketch keeps stroke-only hit-testing so it never shadows nodes beneath its transparent bbox.

### 3.2 Stroke merging is purely spatial ("regions")

On pointer-up a new stroke either starts a fresh sketch node or is appended onto the **nearest existing sketch region** within a screen-space proximity threshold ([findMergeTarget](../../apps/web/src/components/Nodes/sketch/sketchMerge.ts), threshold `SKETCH_STROKE_MERGE_MAX_DISTANCE_SCREEN_PX / zoom`; same parent frame only). Merging is **purely spatial — time plays no role in the boundary**: coming back to write next to an old region still merges into it, so a mid-writing think-pause can never split a line across nodes. It only ever targets one existing region per stroke; merging two existing regions ("bridging") is a later concern. Per-stroke `createdAt` is preserved as intra-region metadata but no longer influences the region boundary; a unified node-level "modified-after-a-gap" provenance is a separate cross-cutting concern (see [sketch-region-redesign proposal](../proposals/sketch-region-redesign.md)).

When a merge expands a sketch region bbox, geometry reads the synchronously authored `style` size before React Flow's asynchronous `measured` echo. Existing stroke coordinates are rebased against that same authoritative size, preventing fractional measurement differences from shifting the region's prior ink.

### 3.3 Draw and erase controls

Desktop and touch input share `toolStore.sketchDraft` and the same mode/parameter components, but expose the frequent mode switch at different levels:

| Input | Pen / eraser entry                                                                                                                      | Parameters                                                              |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| Mouse | The Canvas Toolbar exposes one Sketch button; while active, `SketchSettingsPanel` exposes pen and eraser as compact contextual controls | Color and three editable stroke/eraser size presets appear in the panel |
| Touch | Pen and eraser remain visible in the Canvas Toolbar; tapping either activates Sketch in that mode                                       | The active mode's color and three editable size presets appear above it |

`SketchModeSwitcher` owns the shared `draw` / `erase` store updates. Draw exposes three fixed-position color slots through `SketchColorPresetPicker`, and draw/erase each expose three fixed-position size slots through `SketchPresetPicker`. Each trio is transparent by default; color and size use the same subtle grey slot-level selected surface without an accent ring. Selecting a different slot applies it immediately; selecting the active slot opens the full palette or size slider to edit that slot. Size slots render only a short rounded stroke preview whose height represents the stored value. The preset values, active indices, and current `sketchDraft` preferences persist under the `huabu-sketch-tools` localStorage key through Zustand `persist`; transient `pendingNodeType` does not persist.

During an eraser drag, each hit stroke is hidden immediately through `gesturePreviewStore` so the interaction has live visual feedback. The underlying node data is unchanged until pointer up, when all hits commit as one command batch and one undo gesture; cancelling or switching tools clears the preview and restores every uncommitted stroke.

A selected Sketch node deliberately does not use or mutate these drawing presets. Its toolbar keeps one color menu and one `SketchSizePicker` secondary menu that edit only that node's stored strokes, so post-draw edits cannot silently change future drawing preferences. `SketchControls` owns their shared open state: opening either menu closes the other, and both use the common floating-toolbar popover surface. The thickness slider fires per drag tick, so its drag is bracketed by `canvasStore.beginNodeDataGesture` / `endNodeDataGesture` (arm one pre-edit snapshot on pointer-down, release on pointer-up) — the burst of `MERGE_NODE_DATA` writes folds into a **single undo entry** instead of one per tick. A color pick is a single discrete write and needs no bracket.

### 3.4 Two-layer model: sketch node vs. stroke selection

Mouse hover routing freezes its hit target during a press and observes pointer release/cancellation in the capture phase so descendant gesture handlers cannot leave it frozen. A mouse move with no buttons held also recovers from a release outside the canvas. Hover must resume without an extra activation click; finger selection policy is unchanged.

A sketch participates in the canvas at **two distinct layers**, and keeping them apart is the key to reasoning about selection, movement, and the two AI paths:

- **Node layer (persistent, structural).** A sketch _is_ an ordinary ReactFlow node — it has an `id`, `position`, optional `parentId`, can be framed / reparented / recolored / relabeled / connected, is addressed by node id for snapshots and OCR, and flows through the same engine commands (`SET_NODE_GEOMETRY`, `SET_NODE_PARENT`, `DELETE_NODES`, …) and the same undo pipeline as every other node. Mouse and pen can use **Select** to manipulate the whole Sketch node; finger input treats Ink as transparent for direct selection and drag, so touch users use **Lasso** for deliberate Ink manipulation.
- **Stroke layer (transient, interaction-only).** Individual strokes are **not** nodes: they are entries in the node's inline `data.strokes[]` with no graph id, z-index, edges, or framing of their own. A "stroke selection" exists **only under the Lasso tool** — a transient per-node subset (`gesturePreviewStore.sketchStrokeSelection`, never persisted or undone) that lets the user pick / delete / move / split _part_ of a sketch, which whole-node selection cannot express. Enabling partial operations is the **sole reason** this layer exists.

A sketch therefore has **two independent movement channels**: the whole node moves via the node-drag lifecycle, while a stroke subset moves via a preview translate + on-commit bake. §3.5 covers how the lasso routes into the stroke layer; when a _single_ gesture drives both channels at once (a mixed lasso), they must be reconciled — see the mixed-selection and carried-node notes there.

### 3.5 Stroke-level lasso selection & region editing

Lasso can start on any node's non-interactive surface, including painted Ink and selected Sketch bounds, not only exposed empty canvas. Its shared input policy still reserves controls and editors, and retained-region movement takes priority over starting a new loop. The captured polygon preserves all distinct pointer samples, including browser-coalesced points, so small turns and slow dense sampling do not collapse into straight segments; see [Lasso routing and sampling](./canvas-input-interactions.md#5-lasso-and-sketch-routing).

**Selected-stroke paint.** [SketchStrokePath.tsx](../../apps/web/src/components/Nodes/sketch/SketchStrokePath.tsx) paints every stroke named by `sketchStrokeSelection` with a screen-stable 2px `--color-info` SVG outline beneath the original path. The authored Ink covers the inner half, leaving the same restrained 1px edge and subtle `--color-info-light` glow used by other selected Canvas elements while preserving the authored color and geometry. The core outline is explicit SVG rather than a CSS filter so iPad Safari renders it reliably; chat-reference hover uses the same painter at lower opacity. The emphasis path has no pointer events and is excluded from visible-Canvas grounding capture, while an unselected stroke renders only its original path.

**Toolbar anchor.** `StrokeSelectionToolbar` anchors above the retained `sketchSelectionPolygon` bounds and applies `sketchStrokeMovePreview` while the selection is moving. Whole-node members of a mixed Lasso remain sources but never enlarge the toolbar anchor, so a large Frame or Image cannot push the Ink controls away from the gesture. Source/grounding bounds and new Question placement still use the actual selected content; missing legacy polygon state falls back to the selected-stroke bounds.

Activating Ink Send synchronously freezes the source tree, stroke subsets, source bounds, viewport, crop, and a detached copy of the visible Canvas DOM before asynchronous rasterization begins. The detached presentation preserves Canvas bitmap and live form state, then remains independent of the live React Flow tree. After this snapshot boundary the interaction reservation is released: viewport movement, selection changes, node edits, Lasso dismissal, and Canvas navigation do not recapture, retarget, or cancel the attempt. Durable acceptance clears the retained selection only when its Canvas, node/stroke membership, and Lasso identity still match the submitted snapshot. Retry within the same retained selection session reuses the existing snapshot and Question; a new Lasso session creates a new attempt. A source that is genuinely outside the visible Canvas at activation or a failure to create or rasterize the snapshot still fails explicitly.

Under the **Lasso** tool, selection is split **by node type**: a sketch node contributes only the strokes the lasso actually captured (**stroke-level**), while every other node type is selected **whole** — and the two can coexist in one gesture (e.g. a note plus some sketch ink). A whole sketch enclosed by the lasso therefore yields its strokes, not a movable node; grab a whole sketch as an object with the **Select** tool instead. Lasso and mouse rectangle selection share the node membership and selection session described in [canvas-input-interactions.md](./canvas-input-interactions.md): ordinary nodes require partial intersection and Frames require full containment in the actual shape, not its bounding box. Hidden and unselectable Sketches are excluded from stroke hits. Both node and stroke selection update live during drawing; Sketches never show whole-node selection chrome. Lasso preserves the persisted Layers order even when it selects exactly one ordinary node, so that node cannot temporarily rise above partial Ink that is persistently above it. Release retains the Lasso polygon for a non-empty selection and records node selection once. Cancellation restores the pre-gesture nodes, edges, strokes, and retained polygon without recording a selection action; leaving the canvas never restores its old selection.

The stroke selection lives in `gesturePreviewStore.sketchStrokeSelection` (`nodeId -> strokeIds`, transient — never persisted or undone), is highlighted per stroke in [SketchNode.tsx](../../apps/web/src/components/Nodes/sketch/SketchNode.tsx), and is cleared when the tool changes away from Lasso or an authoritative canvas snapshot replaces the in-memory nodes. The single `gesturePreviewStore.resetCanvasScopedTransients` (fed by one `INITIAL_PREVIEW_DATA` source so it can never miss a field) clears **all** canvas-scoped transients — selection, retained polygon, move preview, carried ids, hover highlight, and the frame/snap/drop previews — on every authoritative geometry swap: canvas switch, authoritative reload, same-canvas SSE snapshot heal, and **undo / redo**. The undo/redo case matters because a retained selection is deliberately kept after a move: without the reset, moving strokes and then undoing would revert the strokes to their old position while the dashed region stayed at the moved position (a delta a generic undo cannot reverse, so the floating selection is dropped rather than re-homed). Hit-testing (`findSketchStrokesInPolygon`) and the anchor bbox (`getSketchStrokeSelectionBounds`) live in [sketchHitTest.ts](../../apps/web/src/components/Nodes/sketch/sketchHitTest.ts); a stroke is captured when at least one of its points lands inside the polygon, using the same even-odd point test as node selection.

**Retained-region move (GoodNotes-style).** On lasso commit the captured flow-space polygon is retained in `gesturePreviewStore.sketchSelectionPolygon` and drawn as a dashed loop by [StrokeSelectionRegion.tsx](../../apps/web/src/components/Panels/Canvas/StrokeSelectionRegion.tsx). The component applies the current viewport transform and live move delta, then portals the screen-space SVG into the React Flow root at the top of the Canvas HUD. It therefore stays above Frames, Images, and every manually ordered node instead of competing with them inside the viewport renderer, but remains visual-only so native connection and resize controls underneath still receive pointer events. A `sketch-stroke-move` recognizer ordered **before** the lasso recognizer in [Canvas.tsx](../../apps/web/src/components/Panels/Canvas/Canvas.tsx) claims an ordinary pointerdown that lands **inside** that polygon from flow-space coordinates and explicitly yields to native node controls; it enters the shared screen-space `canvasGestureSession` pending state and starts moving only after the pointer-specific mouse / pen / touch activation threshold locks. The drag translates the selected strokes live via `gesturePreviewStore.sketchStrokeMovePreview` (a flow delta applied to both the highlighted strokes and the region loop), and on release commits [buildMoveStrokesCommands](../../apps/web/src/components/Nodes/sketch/sketchMerge.ts) per node (bake to flow → offset moved strokes → reframe union bbox) ([useSketchStrokeMove.ts](../../apps/web/src/hooks/useSketchStrokeMove.ts)). Pointer cancellation restores every whole node to its pre-drag position, tears down snap / frame previews, and discards the pending undo snapshot without running drop or reparent resolution. A pointerdown outside the polygon falls through to the lasso (starting a fresh selection). Within a source region a stroke move is a plain in-node translate; dropping onto a _different_ region or blank canvas re-homes the strokes instead (see **Cross-region split / merge** below). When the lasso also caught **whole nodes** (a mixed selection), those selected nodes travel **together** with the strokes: they are driven live through the store's normal drag lifecycle (`onNodeDragStart` → `onNodesChange` → `onNodeDragStop`, so smart-snap / frame re-parenting / autosave behave exactly like a plain drag) and the stroke bake folds into that gesture's single undo entry. Whole nodes whose ancestor is also selected are excluded by walking the complete `parentId` chain, preventing descendants from receiving the group delta twice through nested frames.

**Framed sketch carried by a dragged ancestor.** When a mixed selection includes a frame _and_ a sketch that lives inside it (or any sketch whose `parentId` chain contains a dragged node), that sketch is **carried** by the ancestor's node-drag — ReactFlow already re-transforms its whole SVG by the group delta. Applying the stroke translate on top would move those strokes a **second** time and slide them out of the frame. To reconcile the two channels, [useSketchStrokeMove.ts](../../apps/web/src/hooks/useSketchStrokeMove.ts)`.onPointerDown` walks each stroke-selected node's `parentId` chain against the dragged-node set and publishes the carried node ids on a dedicated transient channel (`gesturePreviewStore.sketchStrokeMoveCarriedNodeIds`); [SketchNode.tsx](../../apps/web/src/components/Nodes/sketch/SketchNode.tsx) skips the move-preview translate for a carried node, and the commit bake skips it too, so the node simply rides along with its frame (its position relative to the frame is unchanged). Top-level sketches lassoed with a frame are **not** carried (empty set → their strokes follow the frame's snapped delta as before).

**Cross-region split / merge (drag).** A **pure** stroke selection (no whole node in the lasso) dropped onto **blank canvas** splits into a brand-new sketch region; dropped onto **another** sketch region it merges into it. On commit [useSketchStrokeMove.ts](../../apps/web/src/hooks/useSketchStrokeMove.ts) hit-tests the drop point in absolute flow (excluding the source regions, topmost wins) and, for a cross-region drop, dispatches the `MOVE_SKETCH_STROKES_TO_REGION` UI intent instead of the in-node translate. [resolveMoveSketchStrokesToRegion.ts](../../apps/web/src/handler/canvasCommand/resolvers/resolveMoveSketchStrokesToRegion.ts) resolves the destination parent frame from the drop point (`resolveFrameAtPoint`) and calls [buildSketchStrokeTransferCommands](../../apps/web/src/components/Nodes/sketch/sketchMerge.ts), which works in **absolute flow** (`getAbsolutePosition`) so transfers across frames stay correct and degrade to the plain in-node math when the parent is unchanged; the source side reuses the extracted pure core `computeEraseCommands` (reflow the remainder, or delete the node when emptied). Splitting **into a frame** shows the same grow-to-fit accept-preview a whole-node drag gets (`computeFrameFit` + `setFrameFitPreviews`); merge / in-place / blank-top-level drops show none. The whole transfer is **one undo entry** — `canvasStore.moveSketchStrokesToRegion` brackets it with `beginNodeDataGesture` / `endNodeDataGesture` (with an empty-op `rollbackGestureSnapshot` guard). Deferred: auto-contact ("bridging") merge, edge rewiring when a source is emptied, and OCR-rerun on split (see the [sketch-region-redesign proposal](../proposals/sketch-region-redesign.md)).

**Toolbar arbitration.** A [StrokeSelectionToolbar](../../apps/web/src/components/Panels/Canvas/FloatingToolbars/StrokeSelectionToolbar.tsx) floats above the stroke selection: on a **pure, single-color** selection it shows color + size controls (reusing [SketchControls](../../apps/web/src/components/Nodes/sketch/SketchControls.tsx), applied only to the selected strokes — the brush preset is untouched). Each color or size tick builds one `MERGE_NODE_DATA` command containing every affected sketch patch, matching the multi-node accent path's atomic update and undo semantics; the size slider's gesture bracket folds all ticks into one undo entry. A **Delete** action (touch only — desktop uses the keyboard) reuses the eraser's `buildEraseCommands` (subset removal → bbox reflow, or node delete when empty). Delete removes the **whole selection** — strokes plus any whole nodes the same lasso caught — as **one undo entry**: the node delete takes its snapshot + intent trace, then the stroke erase folds into that same entry via [commitStrokeCommands](../../apps/web/src/components/Nodes/sketch/sketchMerge.ts) (`foldIntoOpenGesture`), mirroring the mixed stroke-move gesture. **Delete / Backspace** triggers the same combined delete (guarded against text inputs); the canonical keyboard handler in [useCanvasShortcuts.ts](../../apps/web/src/hooks/shortcuts/useCanvasShortcuts.ts) **skips its own node deletion while a stroke selection is active** so the keypress never pushes a second snapshot. To guarantee at most one floating toolbar, the node toolbars (single-select in [NodeWrapper.tsx](../../apps/web/src/components/Nodes/NodeWrapper.tsx) and MultiSelect) hide whenever a stroke selection exists. Pure and mixed Ink selections retain the source count, explicit conversation picker, and submit action. The picker is not a source; lassoed Agent Nodes never determine its destination or contribute source counts. Conversation-first defaults, explicit New, and existing-thread continuation are described in §4.1. Rendering a stroke selection to PNG and sending it to the agent is also covered there. Optional submission-time OCR uses only the explicitly selected strokes as transient Agent evidence and does not persist recognized text into the Sketch; eager/background region OCR remains deferred (see [sketch-region-redesign proposal](../proposals/sketch-region-redesign.md) Stage 3).

An eligible empty-Canvas tap, or an unlocked tap on empty space inside the retained Lasso region, dismisses the complete retained result without creating an undo entry; a locked region gesture still moves it. During Ink Query preparation, a Canvas-scoped transient guard protects the captured selection from dismissal, retained-region movement, and tool-change cleanup; the toolbar keeps its dimensions, disables Send with reduced opacity, and replaces the Send icon with the Lucide `Square` glyph until durable acceptance or a known rejection ends local preparation. This is a disabled pending indicator, not an active Stop control: it retains the square toolbar button shape and exposes the accessible name `Sending ink request`, without a tooltip or visible status text. An ambiguous pre-acceptance transport result retains its acceptance observer for Chat stream reconnect and Stop reconciliation. A confirmed Stop with no acceptance proves that the turn never started, removes that observer, and restores the Send control while preserving the Lasso and Question for retry. The reservation is scoped to the captured polygon/stroke identity: a newer Lasso immediately restores its normal Send state, but it does not discard the older observer, and stale callbacks from the older turn cannot clear it. Until that observer resolves, the shared turn controller rejects another dispatch to the same Canvas/thread instead of replacing the observer; a submission targeting another thread remains independent. Acceptance removes the toolbar only when its captured Lasso still matches. The accepted turn's running status belongs to the Question Node, and ChatPanel owns Stop rather than morphing the completed Lasso surface into a run controller. Finger direct-selection hit-testing excludes the painted Sketch body and continues to ordinary content below, while React Flow resize and connection controls remain interactive and mouse and pen behavior remains unchanged.

From here the sketch is ordinary canvas content that AI can read (§4).

## 4. Read by AI as a content node

No explicit trigger; any agent turn can treat a sketch as visual content:

- `read("nodes/<file>.md")` returns only the sketch's `label`, **not the strokes**;
  to see the drawing use `snapshot_node` to render a PNG vision attachment. Tool
  def: [definitions.ts](../../apps/server/src/modules/agent/tools/definitions.ts),
  impl: [snapshot-node.ts](../../apps/server/src/modules/agent/tools/handlers/snapshot-node.ts).
- The chat route auto-snapshots the user's selected sketch / image on the first
  turn (nodes ≤ 200px cluster into one PNG, strokes over image); keys go into
  user-message metadata so the agent need not re-snapshot.
- External agents: the system prompt says "use snapshot for `sketch` / `image`, not read-node".

### 4.1 Partial stroke selection as AI context

**Node-only Lasso submissions.** A retained Lasso containing Text, Note, Frame, or other ordinary nodes also exposes the destination picker and an explicit **Send selection request** action. Drawing a loop never sends automatically. These turns use `selection-intent`, not `ink-intent`: no synthetic handwriting image, OCR, or mandatory visible-Canvas screenshot is created. They share the existing conversation binding, acceptance/retry, interpretation-history, permissions, and Agent-authored visible Canvas delivery contract. Ordinary click/rectangle selections retain their node toolbars; a retained Lasso owns one toolbar, with no stroke style controls for node-only selections.

Selected Text contributes its **complete body**, frozen with the submitted source snapshot and persisted in `focus.selection.textContents`; it is not clipped to the loop or reduced to a preview. Non-hydrated Text is resolved from storage during envelope preparation and fails explicitly if unavailable. Note contributes an addressable reference and short preview, not its full body. Frame contributes a reference and a **one-level child directory**; nested Frames and their bodies are read on demand. A selected Frame subsumes geometrically selected descendant nodes for submission, avoiding recursive expansion and duplicate context. To submit a child Text directly, select it without enclosing its Frame. Explicit partial Ink inside a selected Frame remains a separate, unique source and retains the existing required Ink image/grounding path. These source rules also apply to mixed Ink/node submissions; ordinary Chat context behavior is unchanged.

The Agent may interpret a clear request in selected Text but must not treat every selected or retrieved document as an instruction. Materials without a clear request require a focused clarification, not a guessed operation. Selection requests preserve source content and place visible replies near the sources after inspecting current layout. Their history uses a selection icon and localized selection wording rather than claiming the user submitted handwriting. The existing `report_ink_intent` / external report endpoint and `inkInterpretation` fields are reused internally for both Canvas input kinds.

Ink history renders the pen icon immediately followed by the interpretation summary (or delivery-state fallback), then any invoked-skill chips and original text. Retry metadata must not insert a skill chip between the icon and summary.

**Canvas-writing destinations.** Ink is an input format whose replies require Agent-authored Canvas changes. The New menu offers built-in Operate and external Agents, not built-in Chat (`ask`). Only resolved internal Ask conversations are excluded from continuation and local/server-recency defaults without changing their mode. Remembered targets with missing thread IDs or invalid bindings remain selected but unavailable until explicit reselection; they are not treated as confirmed Ask conversations or silently replaced with New or another conversation. The implicit built-in default remains Operate. The toolbar revalidates the destination before preparing a new attempt, and the server re-reads the live owner mode after deferred input preparation before admitting internal Ink. Canvas mode edits share the invocation's turn lease, so they cannot race preparation or execution. External conversations retain their session permissions, including planning constraints; their stored `mode: ask` is not the built-in read-only contract. Ordinary text Chat retains both built-in modes. Busy, missing, and invalid targets remain unavailable.

**Agent-authored Canvas replies.** Every successful Ink turn must deliver an actual visible Canvas change through the Agent's normal write operations. The Agent chooses an appropriate editable result: a concise Note, a structured arrangement, or changes to existing objects. Discussion, research, planning, clarification, and inability to interpret also require Canvas replies, without authorizing execution of uncertain or merely discussed work. Huabu no longer converts final chat text into a Note or automatically connects a reply to the Agent Node. Interpretation reports, placeholder naming, read-only tools, and metadata-only edits do not complete the reply. Source strokes remain intact unless the user asks to change them. Failed, interrupted, or permission-blocked turns never fabricate a reply or bypass permissions; ordinary text Chat and automatic panel opening are unchanged.

The host observes persisted, thread-attributed Canvas updates during the invocation, excluding Agent Node lifecycle projections. Both driver adapters verify visible delivery before Agenetes persists successful terminal events; a missing result becomes a durable error shared by the initial stream, reconnect, history, and Agent Node lifecycle. No result delivery depends on ChatPanel being mounted, and verification never creates a Note or edge. Existing historical Notes are not removed or rewritten. See [Agent Architecture](./agent-architecture.md).

**Per-query placement.** Explicit Ink spatial instructions take priority. Without them, the Agent inspects current geometry and places the result near this turn's selected Ink and relevant materials, avoiding overlap and extending their visual structure. The conversation owner is not the reply-placement anchor, especially when successive queries occur elsewhere on the Canvas. The envelope retains per-Sketch selected-stroke bounds in absolute Canvas coordinates, derived from the same prepared snapshot as the required Ink image and rendered for internal and external Agents as `<ink_query_geometry>`. These bounds exclude unrelated strokes in a merged Sketch and account for frame nesting and resize scale. Geometry is historical input evidence; current layout queries determine live obstacles. The host verifies visible writes, not semantic layout quality.

Each Ink message carries an Agent-attributed interpretation for readable history and transparency, separate from Canvas delivery and the original user content. The report is `{ text, explanation? }`: a required one-line summary (at most 120 characters) plus an optional explanation of ambiguity, grounding, or limitations (at most 600 characters). It may express partial understanding or inability to interpret without a semantic category. The Agent may read necessary context before reporting, but reports before substantive edits or a formal answer. Reporting neither grants permission nor decides whether execution or clarification is appropriate.

The shared per-turn directive steers `report.text` toward a direct, natural summary in the input's language, not an Agent-to-user paraphrase prefixed with "You mentioned", "You are asking", or equivalent framing. It preserves questions, discussion, and action requests without turning them all into commands, inventing first-person quotations, or adding unsupported intent. For example, "Why was the previous reply not written to Canvas?" remains a question, not an instruction to write that reply. This is generation guidance for new reports, not client-side prefix stripping or a rewrite of saved history.

The complete confirmed report is projected into `inkInterpretation` on the owning user message through the existing tool events, both live and after history reload. The message bubble shows the Ink-identifying pen icon followed directly by the summary in one naturally wrapping paragraph using the normal body text color. There are no visible “Ink request” or “Agent interpretation” headings, semantic badges, secondary explanation text, or inset interpretation block. Accessible labels retain Ink identification and Agent attribution; the summary remains an interpretation, not typed user text or OCR. The optional explanation remains in the history record and search index. Host-owned delivery states provide explicit pending, missing, failed, interrupted, or legacy-without-text fallbacks in the same inline position. A terminal turn cannot remain pending, and a received report survives subsequent execution failure. Historical `inferred` reports retain their text; historical `clarify` / `unsupported` reports show that no interpretation text was saved instead of inventing one. New writes reject those legacy semantic fields.

The retained-Lasso toolbar has an explicit Agent destination picker with `Continue conversation` above `New conversation`, so an existing current-Space thread is the first visible and keyboard-focused choice when one is available. New conversations use the same default resolution and browser-local Agent recency as ChatPanel; explicit Agent choices update that existing preference without introducing Ink-specific storage. New nodes are created only on send, adjacent to the actual Ink/ordinary sources. Continuation lists current-Space Agent Nodes by conversation title and Agent identity, retaining each thread's binding and mode. Question selection neither changes the destination nor contributes references or source counts, including Questions inside selected Frames. Canvas selection, movement, and deletion still operate normally.

The destination trigger is a content-width control, exempt from the toolbar's fixed-width icon-button styling. The retained-Lasso toolbar omits the source count; source provenance remains visible after submission in ChatPanel. One transparent positioning container owns two sibling toolbar capsules separated by an 8px gap, so they move, clamp, and wrap as one anchored unit without forming one long visual surface. Both capsules use the same 46px single-row shell, 32px controls, 12px radius, surface, border, shadow, and group spacing as the other Huabu contextual toolbars. The left editing capsule begins with a static content identity: the canonical Sketch pencil for a pure-Ink selection, or Lucide `Shapes` for Ink mixed with ordinary nodes, followed by a standard divider. Pure Ink then exposes color and thickness, another divider, and the always-visible overflow menu; a mixed selection proceeds directly to overflow. The overflow menu's only current action is danger-styled Delete; desktop Delete/Backspace remains available. The rightmost Agent capsule contains destination and Send. Move to another Space is intentionally absent because the existing move contract addresses whole nodes and would strand partial Ink, while Copy link is absent because a transient stroke subset has no durable node deep link. Capsules retain their content width and wrap whenever their combined width exceeds the positioning container's available width, rather than shrinking around overflowing controls or relying on a fixed mobile breakpoint. The destination menu opens 8px below its toolbar surface, accounting for the trigger's inset, subject to viewport clamping. When the current Space has no conversations, omit the entire continuation group, including its divider and heading; an all-busy group stays visible with disabled entries.

The positioning container's available width comes from `CanvasFloatingPopover`'s `--canvas-popover-available-width`, calculated against the visible React Flow boundary rather than browser width. Opening or resizing adjacent Chat/preview panels therefore reflows the capsules even when the browser size is unchanged. The destination trigger also caps its width to that boundary minus capsule chrome, spacing, and Send, so a long Agent label cannot overflow its own capsule on a narrow canvas.

Opening the destination menu by mouse, touch, Enter, Space, or ArrowDown focuses its first enabled item; activating the open trigger again closes the menu, and ArrowUp opens at the last enabled item. The destination trigger remains surface-colored while hovered or expanded rather than using the shared grey expanded-button treatment. Because the coordinate-positioned Popover has no floating reference element, the trigger is explicitly excluded from outside-press dismissal; one physical activation therefore reaches the shared `DropdownMenu` toggle exactly once instead of dismissing on pointer-down and reopening on click. Menu navigation skips disabled conversations, and Escape or choosing an entry returns focus to the trigger. Pointer propagation and compatibility-mousedown suppression still protect the retained Lasso while explicit menu focus makes keyboard navigation immediately available after a pointer open.

`Continue conversation` and `New conversation` are peer top-level sections with matching headings and a divider between them. Within New, the shared Agent options render `External Agents` as a subtle, non-uppercase subheading sharing the top-level headings' left alignment, without horizontal rules. ChatPanel retains the shared options' default centered divider heading; only the Lasso picker opts into the subordinate presentation.

The destination trigger's tooltip is the short localized action `Choose Agent session`, not the full conversation title and Agent identity. Its accessible label retains the detailed destination, and unavailable reasons remain available through the accessible description and the menu's status message.

Running or streaming conversations and pending conversation forks are visible but disabled. If a chosen conversation becomes busy, disappears, or loses its thread association, the picker keeps the selection and disables sending rather than silently switching targets. Availability and the captured node/thread association are checked again before dispatch, and the existing server admission remains authoritative. The picker is locked during preparation and ambiguous acceptance reconciliation. Rejected new-node reservations are keyed by captured source selection and destination, so retrying the same attempt does not create another node or send to an earlier choice.

Submission progress is not a destination error. During preparation and acceptance reconciliation, Send is disabled with `aria-busy` and the shared circular-arc Spinner instead of a nonfunctional Stop square. Its fixed square wrapper rotates around the button center and respects reduced motion. Once the dispatch controller starts this attempt, the matching node/thread's normal busy reason is hidden while preparation remains reserved; missing, changed-thread, read-only, or Profile errors are not suppressed. Other running destinations remain disabled with neutral “Processing the previous request” text in the accessible description and menu, without a yellow warning icon. Actual unavailable destinations retain the warning treatment. Acceptance, rejection, and Lasso invalidation clear the local submission ownership.

While no stroke selection is active, the retained-Lasso destination hook prefetches `GET /api/canvas/:canvasId/recent-conversation` for the current Space. A fresh completed Lasso previews that result immediately when available, then refreshes the server-owned target in the background. If an immediate Lasso outruns prefetch, an empty Space previews New mode and a single available conversation is previewed from local Canvas state, avoiding a loading-to-default visual flash; only unresolved candidates show an explicit loading label. A preview is not a confirmed send destination: Send remains disabled until the current read settles successfully and resolves an available target. An explicit picker choice confirms the target immediately and invalidates the pending response, so users can send without waiting and background refresh cannot interrupt preparation. The server-owned recent target is shared across devices and updated by accepted Inquiry and ChatPanel turns anchored to an Agent Node in that Space. It identifies the same node/thread, not a copied context or a new conversation on the same Profile. A remembered target wins even if currently busy, deleted, or associated with a different thread; invalid or busy targets block Send until explicit reselection or restored availability.

The destination draft is local to the retained Lasso and discarded on dismissal or acceptance. Neither merely choosing an entry nor a rejected request updates shared recency. Each next Lasso fetches the server again, including after a ChatPanel turn or an acceptance on another device, but a server-confirmed or manually selected draft does not follow later recency changes. Read failures remain explicit and never default to New; users may choose a destination or reopen the menu to retry. Loading responses from an older Lasso or Space cannot overwrite a newer draft or explicit choice.

`gesturePreviewStore.sketchSelectionSession` is a transient identity created only when the shared area-selection session commits a new Lasso. Preview and cancellation preserve the previous identity, destination draft, and rejected-send reservation; moving the retained polygon preserves them too. A committed replacement receives a fresh identity even for identical strokes and geometry. Dismissal and canvas-scoped resets clear it. Default reads pause during preview; cancellation resumes an interrupted read without allowing its aborted response to overwrite the restored draft.

A stroke selection (§3.5) is a first-class **source**, not just an editing target. `getAgentChatContext` injects the selected strokes into the turn's selected nodes, and `snapshot_nodes` accepts an optional per-node `strokeSubsets` KEEP-list (`[{ nodeId, strokeIds }]`) so the server renders **only those strokes** — content-addressed independently of the whole-node snapshot — and labels the attachment as a partial stroke selection. If a non-empty KEEP-list no longer matches any stroke, the snapshot fails with a stale-selection error instead of widening to the whole sketch. The wire `WireSelectionNode` carries an optional `strokeIds`. Source counts in `ChatContextSources` and the sent user message both count a sketch that has _only_ a stroke selection, so a pure-ink source is visible before and after sending.

**Persistence + hover re-highlight (zero migration).** The sent `strokeIds` already persist with the turn's request (`request.selectedNodes[].strokeIds`), so no new storage is needed; they surface to the client via a message-level `selectedStrokeIds` and the envelope's **optional** `focus.selection.strokeSubsets` (old records simply lack it → graceful degrade). Hovering or tapping a chat message's source chip re-highlights those strokes on the canvas through a **separate** transient channel `gesturePreviewStore.sketchStrokeHighlight` — kept apart from the active `sketchStrokeSelection` so the two never fight — and [SketchNode.tsx](../../apps/web/src/components/Nodes/sketch/SketchNode.tsx) renders `selection ∪ highlight` in the shared `--color-info`. Mouse leave clears the highlight; Canvas empty taps, node taps, and new Lasso interactions also clear it because iPad's synthetic hover may not emit a matching mouse leave. The highlight is **best-effort against the current canvas**: SketchNode only lights strokes still present in its `data.strokes`, so erased strokes / deleted nodes fall out with no cleanup, and a deleted node's chip degrades to the shared [NodeRef](../../apps/web/src/components/Nodes/NodeRef/NodeRef.tsx) strikethrough. The count label shows the number of strokes sent _at the time_ ("N 笔"), never a recomputed value.

When a Lasso includes ordinary nodes as well as Ink, activating Send synchronously freezes the source tree, stroke subsets, viewport metadata, and a detached copy of the rendered Canvas before asynchronous work begins. Loaded same-origin, data-URL, and blob-URL images are materialized into Canvas pixels during that freeze, alongside Canvas bitmaps, current video frames, form values, and nested scroll positions, so later artifact replacement or URL failure cannot alter grounding. Background rasterization produces a bounded relationship PNG from this detached presentation, preserving the activation-time semantic zoom/LOD and Ink landing position while suppressing interaction chrome and selection highlighting. Navigation, viewport changes, source edits, and selection changes after Send do not mutate or cancel the attempt; a rejected retry reuses the same captured sources, visual snapshot, destination, and Question. The image is durable Agent grounding rather than a Chat attachment: it does not add a source, chip, thumbnail, or download row. Built-in Ink turns report their interpretation through the turn-scoped `report_ink_intent` tool; the original user content remains empty.

External Ink turns reuse these same images and canonical ACP content blocks, with no additional rasterization or download requirement. A turn-specific RFS report endpoint replaces the built-in-only `report_ink_intent` call; its lifecycle is activated by external dispatch and invalidated on completion, failure, or cancellation. The shared writer protects user titles, and confirmed reports enter the same interpretation projection as built-in reports. See [Agent Reachback](./agent-reachback.md#agent-control-plane) for the authenticated report contract. Image input requires the external Agent's advertised ACP image capability and a vision-capable model; no built-in model fallback is used.

### 4.2 Handwritten `#` resource references

Reference highlights are portalled into an inert, pointer-transparent host inside the corresponding Sketch node, immediately below its stroke SVG. They follow the same effective stacking order as Canvas, including sole-node and Frame-subtree selection elevation: above lower backgrounds but below the original Ink, without blend modes or stroke recoloring. A binding split across Sketch nodes uses the lowest-painted source node so the highlight stays below every source stroke. Highlight bounds are converted from Canvas coordinates into the host's local coordinates using the same geometry-preview tree as the label. If React Flow culls that source while the semantic label still intersects the viewport, the highlight uses a viewport portal at the preceding integer z-index; the portal follows the node renderer, so it paints above lower nodes while remaining below all source Ink. Remounting restores the node-local host without duplicate highlights. Labels and hit targets remain in the Canvas overlay.

Canvas PUT validates optional persisted bindings against the shared strict schema before saving. The shared CREATE_NODES and MERGE_NODE_DATA handlers reject malformed incoming Sketch bindings with `invalid-target`. Projection also checks legacy/restored metadata with a zod-free runtime guard before iterating source IDs: malformed bindings produce an explicit diagnostic containing node/stroke identity and are excluded from projection, without deleting or mutating the Ink. Guard/schema parity tests cover supported types, bounded strings, fingerprints, unknown fields, and exactly four unique source IDs. Shape-valid bindings with changed source geometry still follow the reversible invalidation rules below.

Annotation placement reuses the Canvas geometry-preview tree, including ancestor offsets and source-node size previews. Canonical geometry still owns binding validity and writes; transient reflow can reposition or resize the displayed hash without invalidating its stored binding. Labels, highlights, and both hit targets disappear if any source owner is hidden or suppressed by the shared Frame zoom policy, including bindings split across multiple Sketch nodes. An open picker is dismissed when its sources become invisible. Visibility recovery restores the annotation without changing the durable binding.

Rejected-send reservations are keyed only by stable source selection, destination, and retained-Lasso session identity, not by live Sigil labels or bounds. Renaming a resource before retry therefore reuses the reserved Question and the original frozen references, source context, and grounding image instead of creating or capturing another attempt.

Grounding rasterization resets both physical and logical positioning offsets on the cloned root. The mounted snapshot remains offscreen, but its copied `inset-inline` values must not move the rasterized content outside the PNG.

Resolved labels use bundled Caveat (Latin) and LXGW WenKai Lite (Chinese), with one mixed-language stack exported by [nodeFontConfig.ts](../../apps/web/src/utils/node/nodeFontConfig.ts). Existing Text nodes retain their legacy `hand` font stack. Labels inherit their source stroke's color and use Inkitiate's 16–34px sizing and 8px text gap. Short names fit their content; long names wrap at 288px with 1.1 line-height, at most two visible lines, and an ellipsis beyond that limit. Long unbroken names also wrap. The hash aligns with the first line, the highlight expands with measured text height, and the tooltip retains the full name. The `ink-reference-highlight` semantic token follows the reference's pale green background at 70% opacity without altering global success colors. Measurement observes font-driven width and height changes; Send reports fonts that are not ready rather than freezing fallback typography into the grounding image. Fonts and license notices are bundled locally, with no runtime font CDN dependency.

The resource picker follows Inkitiate's compact styling, widened to 288px, with an opaque surface, border, 6px corner radius, 8px padding, shadow, and a 6px anchor gap. A resolved reference anchors the picker to the full measured hash-and-label bounds, including both text lines, rather than the strokes alone. The shared popover places it below those bounds and flips above when needed, preserving the gap through font loading, wrapping, and Canvas zoom. An unbound hash still anchors to its strokes. The heading is 10px; resource rows use the shared small Button at 24px height with 4px spacing and bare type icons. Available category tabs reuse [TabGroup.tsx](../../apps/web/src/components/Common/TabGroup.tsx) in Docs (PDF), Web, Images, and Text (Note/Text) order; categories without eligible current-Space resources are hidden. There is no search field, collapsible group, decorative icon tile, or persistent hint footer. The tabs remain outside a single bounded, virtualized list viewport. The scrollbar reuses Notes' inset capsule thumb through [scrollbar.css](../../apps/web/src/components/Common/scrollbar.css). Width is clamped to the available Canvas independently of zoom.

Each category tab pairs its text label with the canonical Canvas type icon from [nodeIcons.ts](../../apps/web/src/config/nodeIcons.ts): FileText for Docs, Globe for Web, Image for Images, and Type for Text. Tabs have a fixed 50px width and align left with 4px gaps rather than stretching to fill the row. Five tabs occupy 266px of the default panel's 270px content width, reserving room for a future category without enabling Frame references. Labels use 11px text beside 12px icons with a 2px internal gap; the 32px hit-target height is unchanged. Narrow Canvas bounds allow wrapping instead of horizontal scrolling. Common TabGroup accepts an optional decorative icon hidden from assistive technology; the visible label remains the accessible name. Icons inherit the selected/unselected text color, without colored tiles or an additional icon mapping.

The English image-category label is shortened to "Image" so the icon and label fit the compact tab without clipping or reducing text size further.

The shared CanvasFloatingPopover publishes Floating UI's nonnegative available width and height as CSS variables. The Sigil picker opts into the available-height limit so its list shrinks to fit above or below the reference in short viewports while the heading and tabs remain fixed. Other popovers retain their existing height behavior unless they consume that variable.

Handwritten `#` recognition is a built-in drawing interaction with no enable/disable setting; an older persisted disabled preference is ignored and no longer written. Detection examines only the latest four locally committed strokes in the current Canvas session, normalized into Canvas coordinates across Sketch regions. The hash-only geometry rules adapt Inkitiate revision `31bc7e9279ef8b4c7529cc31e1fac9eaf8fd51bf`: minimum length 7, curvature ratio at most 0.28, axis deviation at most 35 degrees, within-pair direction difference at most 25 degrees, length ratio at most 2.5, and four actual polyline intersections. Huabu uses its existing stroke `createdAt` timestamps for the four-second window. A new drawing down cancels the 400 ms publication timer. Reload, remote updates, Undo/Redo, and paste do not rediscover historical hashes. There is no `//` detector, OCR, network recognition, or automatic submission.

The anchored picker groups current-Space eligible nodes by category, regardless of provenance, preserving canonical node order within each category. New bindings open Docs if nonempty, otherwise the first nonempty category. Reselection opens the existing binding's category only if it still has candidates; otherwise it falls back to the first available category. Tabs update as resources are added or removed. If the active category becomes empty, the picker switches to the first available category and resets scrolling and keyboard position. When no eligible resources remain, hide the tab bar and show a single no-resources message. Switching categories never mutates Canvas nodes or persists a preference. Arrow keys, Home, and End move between visible tabs; Tab enters the list, whose arrow/Enter navigation remains available. Frame references are not supported and no Frame tab is shown. The heading explains both binding paths: click a Canvas object or choose a resource from the list. There is no remove-reference action in the picker. A pending tap can bind any eligible Canvas resource regardless of the active category without drawing or selecting it; moving past the normal drag threshold resumes drawing. Escape, blank taps, outside UI taps, switching tools, or starting another stroke dismiss the interaction. In Draw or Select mode, activating either the handwritten hash's bounds or its resolved label permits reselection; cancellation preserves the existing binding. Both hit targets retain native pointer ownership above the drawing overlay and become pointer-transparent during Lasso, Pan, erasing, or other node placement. The hash's invisible hit target is excluded from grounding; keyboard activation remains on the visible label.

One optional `SketchStroke.resourceBinding` on the first source stroke stores `{id, fingerprint, strokeIds, targetNodeId, targetType, label}`; `strokeIds` names exactly four unique strokes, not their owning nodes. Choosing an eligible resource from the list or Canvas applies `MERGE_NODE_DATA` and closes the picker synchronously, before awaiting the existing submission save barrier. Further choices remain available during persistence; the shared saving flag stays active until all in-flight saves settle. Failures report an error and restore a valid retry picker only if the user has not moved on to another interaction or Canvas. A stale save completion never closes or replaces a newer picker. Persistence continues through normal undo/sync. The projection resolves current stroke owners and validates a translation/uniform-scale-invariant geometry fingerprint. Source edits or partial transforms hide the annotation but retain the stale record, allowing Undo to restore it; unrelated added strokes and ownership rebasing preserve it. Missing or type-changed targets remain explicit broken references. Clipboard copies and cross-Space moves strip bindings rather than carrying invalid identities.

A direct drag from either the hash or label moves exactly its four source strokes together with the annotation. [useInkSigilDrag.ts](../../apps/web/src/components/Nodes/sketch/useInkSigilDrag.ts) uses the existing pointer-specific activation thresholds, stroke move preview, `buildMoveStrokesCommands`, and `commitStrokeCommands`: source regions reframe in place, unrelated strokes and target resources stay put, and the move is one normal undoable command batch. A short tap still reopens the picker; completed drags suppress compatibility clicks. Escape, pointer cancellation, scope changes, and source updates discard the preview. Direct dragging does not create a separate label position or move selected ordinary nodes.

Labels follow the current target name, Canvas transform, and complete retained-Lasso move preview, avoiding double translation for nodes carried by a Frame. Erase previews and partial moves hide affected annotations. A pointer-transparent highlight renders below the node renderer; labels render above the drawing overlay. Measured visible label width and height feed the shared layout and frozen capture bounds, including both wrapped lines. Labels never consume Lasso gestures. Only a valid binding whose four strokes are selected becomes an `inkResources` entry, with at most 32 entries per turn; partial selections remain ordinary Ink with a nonblocking indication. Pending or included broken references require resolution before Send.

Selected labels/highlights join the synchronous grounding freeze even for an Ink-only selection; unselected or partial annotations are excluded. Referenced resources do not enlarge the crop, change the actual selected-node tree, choose a conversation, or grant permissions. Frozen references survive retries and appear as deduplicated source chips in history. See [Agent Context](./agent-context.md) for server validation and canonical resource preparation. Automated geometry, state, component, request, and renderer tests cover the implementation; real iPad/Pencil precision, latency, and large-Space acceptance remain unverified.
