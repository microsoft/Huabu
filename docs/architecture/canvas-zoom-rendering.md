### Frame Width Tiers

Frame layout and visual metrics share one width-only tier: compact below 900 canvas units, regular from 900 to below 1800, and large from 1800 upward. Height does not affect the tier; invalid or missing widths use 1200. Title font sizes remain 24 / 36 / 52, corner radii remain 16 / 24 / 32, header insets are 64 / 96 / 152, and content padding and gaps are 20 / 28 / 40. The shared canvas engine owns tier selection and spacing for both browser and server layouts; the frontend adds typography and corner radii from that same tier. Hug sizing resolves the smallest self-consistent tier from the final outer width. Existing manually positioned children are not repositioned merely by rendering a Frame, and the title's horizontal alignment still follows the existing child inset. Far-zoom typography remains screen-space based.

### Far-Zoom Text Labels

Note, Web, PDF, Office and Video minimal labels reuse `SemanticPlaceholder`, `FarZoomLabel` and `farLabelContentBox`. The shared content-box calculation subtracts the existing insets and allocates every complete title line that fits, without a fixed three-line cap. Descriptions use remaining complete lines only after the title fits in full. Existing fonts, node geometry, insets and presentation thresholds remain unchanged.

Note far-zoom labels separate the title and description with spacing only; no divider is rendered.

The canvas supports zoom values from `0.01` through `5`, with the shared bounds in [`apps/web/src/config/canvas.ts`](../../apps/web/src/config/canvas.ts) applied to React Flow and the custom pinch handlers.

Office overview cards share the PDF PreviewCard surface policy: `bg-surface` without an accent, and `noteSurfaceStyle` for an accent-tinted surface. The Office cover and footer remain transparent over that common fill; file-format icons, content, and actions are unchanged.

Frame region labels retain the original `headerMetrics` position and width, with fixed screen-space 11px text, weight 500 and 16px line height, approximating the Note far-label 10px/14px ratio. Their rendered line count uses the actual screen height below that title position, reserving the existing Frame edge inset at the bottom; the conservative region takeover fit threshold remains separate and unchanged, including its 49px minimum screen height. A trailing count badge replaces the leading accent dot only in the far-zoom label. It reuses `FrameNode`'s direct-child count (a nested Frame counts once), with accent-derived foreground and fill or neutral tokens for white/unset accents. The badge has a 10px height and minimum width, 7px numerals, 2px horizontal padding and a 6px horizontal title gap. Its 3px block margins center the badge within the 16px title line; multiple digits expand its width. An accessibility-hidden natural-flow probe measures whether the complete title and badge fit within the available height with the badge on the title's last line; `ResizeObserver` refreshes this decision when that layout changes. This inline presentation is preferred for both single-line and multiline titles. Otherwise the clamped-title fallback reserves one complete line for the badge, outside the clipped text, and uses wrapping flex layout so a badge on a new line has no leading indent. This preserves a visible grouping indicator without reserving a permanent column or changing normal Frame headers. Browser text layout owns wrapping and native multiline ellipsis; fitting Latin words wrap intact, overwide words may break, and the final clipped line can still truncate within a word. Neither layout path performs manual word truncation or writes canvas geometry.

While a Frame region label is visible, its existing portal paints a uniform 60%-opacity veil across the entire Frame above child shells and below the label. The veil reuses `frameSurfaceStyle` for the Frame background and `frameVisualMetricsForSize` for its rounded corners; it has no blur, gradient, border or pointer events. Only the veil has reduced opacity, so the title and count remain fully opaque. It follows the existing region visibility and stacking policy, disappears when the normal header returns, and does not change node geometry or interaction targets. Count badges use the existing accent `highlightBg` fill, or a neutral mix of 12% `--fg-default` into `--bg-hover`, for stronger separation than the original surface tint.

### 3.1 Continuous zoom takeover (question node)

Question retains the existing takeover portal and transient anchor store. `resolveQuestionStage` enters far zoom when `effectiveFontSize * zoom` is strictly below 5 screen pixels and restores the readable card at 5.5 screen pixels or above; between these boundaries it retains its preceding stage, initialized readable. The Question-only default is `QUESTION_NODE_DEFAULT_FONT_SIZE` (24px), giving thresholds of approximately 20.83% and 22.92% viewport zoom. Stored fonts and live resize fonts participate. Node width, height and selection do not select the font stage; Frame suppression independently forces the collapsed presentation without overwriting that stage's history.

The Agent avatar body diameter is 75% of the current card's shorter dimension. `useNodeTakeover` scales the 128-unit artwork, whose avatar occupies 66%, to that diameter: `authoredSize = min(width, height) * 0.75 / 0.66`. Viewport zoom uniformly scales every detail, including ring thickness, inset, approval satellite and speech bubble. There are no screen-size floors, inverse-size compensation, or gamma curves. Width-only reflow can change the shorter dimension and therefore the mark size; font size controls the stage rather than directly setting the mark diameter.

The original node rectangle remains in the canvas store without geometry or persistence writes. The visible mark bounds are centered in that rectangle. `QuestionTakeoverMark` reports a dimensionless visible-bounds ratio through `TakeoverState.onBoundsChange`, including the ring, bubble tail and approval satellite in avatar presentation. The portal publishes its canvas-space center and radius to `nodeCollapseStore`. The 128-unit artwork basis is not a fixed canvas footprint, painted plate or selection rectangle. Settled canvas-space anchors are invariant under pan and zoom.

The retained 200ms reversible progress drives card opacity `1 - progress`, portal opacity `progress`, and the chrome blend from card to visible mark bounds. The mark stays centered, with no corner glide. Initial measured far presentation settles immediately. `NodeWrapper` supplies the mounted shell through a state-backed callback ref so the takeover layer synchronizes card opacity on initial load and shell replacement, even when progress does not change. At zero progress the portal is hidden, inert and accessibility-hidden. Frame suppression hides the Question shell and forces a plain circle (`presentation="dot"`) with no avatar, ring, satellite or bubble; the circle retains mark interaction and anchor publication. Missing-file gating remains unchanged in `NodeWrapper`.

Outside Frame suppression, open state is independent of lifecycle. `QuestionTakeoverMark.isOpen` selects the bubble without replacing approval/running/stored status; legacy `status="open"` remains a fallback if the prop is omitted. The bubble uses the C card's semantic state background and light boundary: info for running, warning for approval/conflicts, danger for error, success for unread completion, neutral for idle/viewed. Closing restores the underlying ring and running motion. Running sweep, approval hold ring/shield, unread/conflict ring and unviewed error segmentation retain their meanings, with proportional authored geometry and no fixed-screen halo. Idle nodes also retain the complete Agent avatar.

Selection, toolbar and handle anchors use the published visible bounds through `blendedMarkRect`, not the retired screen-size reconstruction. The portal retains `useTakeoverMarkDrag`, labelled keyboard/click activation, double-click passthrough and `nopan` handling. Edges still use React Flow's measured handles, and resize controls remain suppressed while collapsed.
