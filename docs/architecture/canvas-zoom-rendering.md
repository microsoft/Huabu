### Frame Width Tiers

Frame layout and visual metrics share one width-only tier: compact below 900 canvas units, regular from 900 to below 1800, and large from 1800 upward. Height does not affect the tier; invalid or missing widths use 1200. Title font sizes remain 24 / 36 / 52, corner radii remain 16 / 24 / 32, header insets are 64 / 96 / 152, and content padding and gaps are 20 / 28 / 40. The shared canvas engine owns tier selection and spacing for both browser and server layouts; the frontend adds typography and corner radii from that same tier. Hug sizing resolves the smallest self-consistent tier from the final outer width. Existing manually positioned children are not repositioned merely by rendering a Frame, and the title's horizontal alignment still follows the existing child inset. Far-zoom typography remains screen-space based.

### Far-Zoom Text Labels

Note, Office and Video minimal labels reuse `SemanticPlaceholder`, `FarZoomLabel` and `farLabelContentBox`; Web and PDF retain `PreviewCard`. All far-zoom titles share 12px text, 16px line height and weight 500 with Frame region titles. Descriptions use regular-weight 10px / 16px `text-fg-muted` text after a 2px gap, and appear only when the full title and at least two complete description lines fit. Video retains its title-only placeholder. The text-only label calculation allocates every complete title line that fits, without a fixed three-line cap. Node geometry and insets remain unchanged.

PDF/Web retain their cover, authored orientation, metadata policy and summary line caps. Far titles use every complete line that fits rather than a fixed two-line maximum, independently of whether a summary exists. Vertical far cards reserve the design's existing quarter-inner-width cover budget before allocating title and description lines, so text cannot consume the entire cover. Horizontal cards budget text within their existing information column; text-only cards use the existing information area. Descriptions appear only after the full title fits. Normal overview cards retain their original typography, title clamping and one-line description eligibility; reading views are unchanged.

Note far-zoom labels show a 10px / 16px description in regular-weight `text-fg-muted` after a 2px gap, with no divider. `noteFarDescription` derives the first useful prose paragraph from existing Markdown, skipping headings, code, lists, image captions and title duplicates. The description appears only when the full title fits and at least two complete description lines can fit in the remaining space (34px including the gap). This is a space budget, not a minimum excerpt length or a two-line maximum. It does not affect title visibility or zoom thresholds. Authored Note content and normal rendering are unchanged, and no separate description is stored.

Ordinary far labels use up to 6px horizontal padding per side. The shared fit calculation reduces that padding before hiding the title, reserving one em of title width (12px) whenever the inner node width permits it; the renderer consumes the same computed inset and typography. At least one complete 16px line must fit vertically. Notes enter minimal mode strictly below 25% and restore ordinary content at 28% or above; between these boundaries they retain the preceding mode, initialized overview. Other opted-in node types retain 20%/24%. Frame regions enter strictly below 10% and exit at 12% or above, retaining the previous state between those boundaries and still requiring the existing label-fit checks. A 240 × 180 Note with 3px borders needs approximately 9.2% zoom to fit a 16px line; a fitting parent Frame now takes over before that title disappears while zooming out. Smaller Notes or unfit Frames still depend on the existing geometry budgets. These zoom bands do not change text-fit budgets, description allocation or node geometry.

The canvas supports zoom values from `0.01` through `5`, with the shared bounds in [`apps/web/src/config/canvas.ts`](../../apps/web/src/config/canvas.ts) applied to React Flow and the custom pinch handlers.

Office overview cards share the PDF PreviewCard surface policy: `bg-surface` without an accent, and `noteSurfaceStyle` for an accent-tinted surface. The Office cover and footer remain transparent over that common fill; file-format icons, content, and actions are unchanged.

Frame region labels retain the original `headerMetrics` vertical position and wrapping width, with fixed screen-space 12px text, weight 500 and 16px line height. Both best-effort eligibility and rendering use `frameRegionContentBox`, which takes the header's actual width and the screen height below its title position, reserving the existing Frame edge inset at the bottom. Preferred nested handoff keeps its conservative 28px × 49px threshold and 2px recovery margin; when no preferred-fit ancestor takes over, a fallback region needs only positive actual content width and one complete 16px line. It does not subtract a second fixed screen-space padding budget. The standalone Frame specimens in the design playground use the same header metrics and enable this fallback too. A trailing count badge replaces the leading accent dot only in the far-zoom label. It reuses `FrameNode`'s direct-child count (a nested Frame counts once), with accent-derived foreground and fill or neutral tokens for white/unset accents. The badge has a 10px height and minimum width, 7px numerals, 2px horizontal padding and a 3px horizontal title gap shared by measurement and rendering. Its 3px block margins center the badge within the 16px title line; multiple digits expand its width. An accessibility-hidden natural-flow probe measures whether the complete title and badge fit within the available height with the badge on the title's last line; `ResizeObserver` refreshes this decision when that layout changes. This inline presentation is preferred for both single-line and multiline titles. Otherwise the clamped-title fallback reserves one complete line for the badge, outside the clipped text, and uses wrapping flex layout so a badge on a new line has no leading indent. This preserves a visible grouping indicator without reserving a permanent column or changing normal Frame headers. Browser text layout owns wrapping and native multiline ellipsis; fitting Latin words wrap intact, overwide words may break, and the final clipped line can still truncate within a word. Neither layout path performs manual word truncation or writes canvas geometry.

The visible title fragments and count badge form one horizontally centered block within the Frame, while individual lines remain left-aligned. The existing measurement lifecycle also reads the rendered block, excludes line-clamped hidden fragments, and translates the block without narrowing its wrapping width or triggering a second text layout. Since DOM ranges omit the browser-painted ellipsis, clamped titles include its separately measured width after the final visible fragment, bounded by the title's clipping box. The ellipsis probe inherits the title typography and participates in the same font-change measurement lifecycle. The label's available-width container is itself centered on the Frame, so authored child alignment does not bias the result. A badge-only fallback is centered as well. Resize observation covers both the natural-flow probe and the visible block, and Frame and ordinary far labels share one font-change subscription. This is a presentation-only adjustment: normal Frame headers, Note labels, vertical placement, fit budgets, ownership, and persisted geometry are unchanged.

While a Frame region label is visible, its existing portal paints a uniform 60%-opacity veil across the entire Frame above child shells and below the label. The veil reuses `frameSurfaceStyle` for the Frame background and `frameVisualMetricsForSize` for its rounded corners; it has no blur, gradient, border or pointer events. Only the veil has reduced opacity, so the title and count remain fully opaque. It follows the existing region visibility and stacking policy, disappears when the normal header returns, and does not change node geometry or interaction targets. Count badges use the existing accent `highlightBg` fill, or a neutral mix of 12% `--fg-default` into `--bg-hover`, for stronger separation than the original surface tint.

### 3.1 Continuous zoom takeover (question node)

Question retains the existing takeover portal and transient anchor store. `resolveQuestionStage` enters far zoom when `effectiveFontSize * zoom` is strictly below 5 screen pixels and restores the readable card at 5.5 screen pixels or above; between these boundaries it retains its preceding stage, initialized readable. The Question-only default is `QUESTION_NODE_DEFAULT_FONT_SIZE` (24px), giving thresholds of approximately 20.83% and 22.92% viewport zoom. Stored fonts and live resize fonts participate. Node width, height and selection do not select the font stage; Frame suppression independently forces the collapsed presentation without overwriting that stage's history.

The Agent avatar body diameter is 75% of the current card's shorter dimension. `useNodeTakeover` scales the 128-unit artwork, whose avatar occupies 66%, to that diameter: `authoredSize = min(width, height) * 0.75 / 0.66`. Viewport zoom uniformly scales every detail, including ring thickness, inset, approval satellite and speech bubble. There are no screen-size floors, inverse-size compensation, or gamma curves. Width-only reflow can change the shorter dimension and therefore the mark size; font size controls the stage rather than directly setting the mark diameter.

The original node rectangle remains in the canvas store without geometry or persistence writes. The visible mark bounds are centered in that rectangle. `QuestionTakeoverMark` reports a dimensionless visible-bounds ratio through `TakeoverState.onBoundsChange`, including the ring, bubble tail and approval satellite in avatar presentation. The portal publishes its canvas-space center and radius to `nodeCollapseStore`. The 128-unit artwork basis is not a fixed canvas footprint, painted plate or selection rectangle. Settled canvas-space anchors are invariant under pan and zoom.

The retained 200ms reversible progress drives card opacity `1 - progress`, portal opacity `progress`, and the chrome blend from card to visible mark bounds. The mark stays centered, with no corner glide. Initial measured far presentation settles immediately. `NodeWrapper` supplies the mounted shell through a state-backed callback ref so the takeover layer synchronizes card opacity on initial load and shell replacement, even when progress does not change. At zero progress the portal is hidden, inert and accessibility-hidden. Frame suppression hides the Question shell and forces a plain circle (`presentation="dot"`) with no avatar, ring, satellite or bubble; the circle retains mark interaction and anchor publication. Missing-file gating remains unchanged in `NodeWrapper`.

Outside Frame suppression, open state is independent of lifecycle. `QuestionTakeoverMark.isOpen` selects the bubble without replacing approval/running/stored status; legacy `status="open"` remains a fallback if the prop is omitted. The bubble uses the C card's semantic state background and light boundary: info for running, warning for approval/conflicts, danger for error, success for unread completion, neutral for idle/viewed. Closing restores the underlying ring and running motion. Running sweep, approval hold ring/shield, unread/conflict ring and unviewed error segmentation retain their meanings, with proportional authored geometry and no fixed-screen halo. Idle nodes also retain the complete Agent avatar.

Selection, toolbar and handle anchors use the published visible bounds through `blendedMarkRect`, not the retired screen-size reconstruction. The portal retains `useTakeoverMarkDrag`, labelled keyboard/click activation, double-click passthrough and `nopan` handling. Edges still use React Flow's measured handles, and resize controls remain suppressed while collapsed.

### Viewport zoom menu

The bottom-left viewport control is a fixed-width percentage-and-chevron trigger, implemented in [`CanvasZoomMenu`](../../apps/web/src/components/Panels/Canvas/CanvasZoomMenu.tsx). It displays the live integer percentage for wheel, pinch, shortcut, and programmatic zoom without exposing a second persistent toolbar. The shared `DropdownMenu` opens above the trigger and contains a percentage input, zoom in/out, reset to 100%, fit all content, and fit selection. Enter applies a finite percentage within the shared 1%–500% bounds; invalid input stays open with an inline error. Fit actions reuse `fitNodesOnCanvas` so unmeasured offscreen nodes and overlay insets retain the same reliable bounds behavior. Fit selection is disabled without visible selected nodes, and fit all is disabled without visible nodes.

Opening focuses the percentage input after the floating panel is positioned; arrow keys move through enabled controls, Escape dismisses, and dismissing returns focus to the trigger. The trigger has an opaque `bg-surface` background and a light border, with a fixed 72px wide by 34px high outer footprint, 16px horizontal margins, and a 24px bottom margin. Percentage text and the chevron form one centered group with a fixed 4px gap; one-, two-, and three-digit percentages never resize the outer control. Its bottom edge aligns with the main toolbar while remaining shorter; the main toolbar retains its existing size, spacing, and bottom offset while centring horizontally on the uncovered Canvas area. The menu reuses the shared floating-chrome surface and semantic colors. Zoom changes are immediate rather than animated, including for reduced-motion users. There is no canvas-wide interactivity lock.

The menu displays platform-formatted hints from the canonical shortcut catalog: Cmd/Ctrl + plus/minus zoom in/out, Cmd/Ctrl+0 resets to 100%, Shift+1 fits all visible nodes, and Shift+2 fits the visible selected nodes. The same catalog supplies the keyboard help. `useCanvasShortcuts` owns these bindings and yields to editors, IME composition for the new reset/fit actions, panels, dialogs, and menus; fitting an empty scope leaves the viewport unchanged. Physical digit-key aliases keep Shift+1/2 working when a keyboard layout produces punctuation. Menu and keyboard fit actions both call `fitCanvasContent`, which delegates to the reliable `fitNodesOnCanvas` bounds path.
