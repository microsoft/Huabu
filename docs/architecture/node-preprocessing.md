# Node Preprocessing

> How canvas nodes are preprocessed: a single 6-stage server pipeline that
> normalises content, optionally enriches it with one LLM stage, and persists
> knowledge sources. Participating node types run the same pipeline; a per-type profile
> decides which stages execute.

> Last updated: 2026-11-20

---

## 1. Two concepts kept separate

- **`CanvasNodeType`** ([shared](../../packages/shared/src/types/canvas/node.ts)) — the 11 node kinds (`note` / `text` / `web` / `pdf` / `office` / `image` / `video` / `audio` / `frame` / `sketch` / `question`).
- **`Capability`** — what a node participates in; each node's profile lists its capabilities and the dispatcher runs capabilities, not routes.

A node is processed by asking "which capabilities are dirty for this change", not "is this an ingest or a label request".

The `fileReference` type is metadata-only, with no extraction, enrichment, content fetch or watched fields. Its label is persisted through normal Canvas sidecar writes; opening its read-only Preview uses the separate [device-files](./device-files.md) service and never triggers preprocessing.

## 2. Pipeline (6 stages)

The dispatcher skips stages whose capabilities aren't in the node's profile. **For ordinary node preprocessing, all LLM / paid-provider work lives only in Enrich.** Questions retain the same preprocessing entry but delegate naming to `ConversationTitleService.initializeQuestion()` before the stage runner; they do not run a parallel Enrich naming path or return an automatic label patch.

| Stage           | Purpose                                                                                                                                             | LLM?    | Persist?           |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ------- | ------------------ |
| 1 Input Resolve | normalise raw node data into canonical input (resolve URL, artifact path, child labels)                                                             | no      | no                 |
| 2 Extract       | parse / fetch content — text / pdf (`pdf2md`) / web (Tavily) / office / youtube loaders                                                             | no      | no                 |
| 3 Normalize     | canonical content, title, metadata merge (web/pdf cache short-circuit on unchanged `src`)                                                           | no      | no                 |
| 4 Enrich        | `generate_label` / `generate_summary` / `generate_keywords` via `ProviderManager`                                                                   | **yes** | no                 |
| 5 Persist       | update an existing node `.md` via the storage `updateNode` coordinator (serialized + rev-CAS), content-equality dedup, placeholder for empty/failed | no      | yes (policy-gated) |
| 6 Project       | assemble authoritative `patch` + diagnostics for the client                                                                                         | no      | no                 |

Web / pdf skip Stages 2–5 when `src` is unchanged and content is cached on disk ([cache-check.ts](../../apps/server/src/modules/preprocessing/stages/cache-check.ts)); `force=true` overrides. `allowLLM=false` / interactive mode → Enrich skipped, result still valid.

Fresh remote PDFs are localized during preprocessing. Extract downloads the PDF once and returns both parsed text and the original bytes; before Normalize, the pipeline writes those bytes to the Space BlobStore as `artifact-<id>.pdf` and replaces the resolved source with that artifact key, so Persist and Project move the node from the remote URL to the canvas-local source used by thumbnails, expanded preview, and download. Existing remote-URL PDF nodes bypass the text cache once to perform the same migration; after `src` becomes an artifact key they resume normal cache short-circuiting. Blob snapshot failure is a warning rather than an extraction failure, leaving the remote URL usable online.

Before preprocessing, an agent-authored `web.src` is normalized at the server executor boundary: any canvas-local `.html` file is imported into `.artifacts/` and persisted as a bare artifact key (uploads staged under `.upload/` are reclaimed), while live `http(s)://` and self-contained `data:` URLs remain unchanged; other local extensions are not imported or reclaimed. Input Resolve then maps the artifact key to an absolute local path for extraction, while remote and `data:` sources continue through the URL path.

Text enrichment and Frame titles use the explicit Utility Agent through `ProviderManager` -> `runFunctionalText()`. Built-In Pi reuses `llmComplete` with the existing `contentMeta`/`frameLabel` roles and Utility/Chat model resolution. External Utility Agents use an Agenetes ACP Job. Existing prompts and projection/persistence paths remain unchanged. The caller supplies the Space identity; each external task uses a separate ACP session without creating a visible Agent Node, reusing a chat session, recording a conversation in Agenetes, or changing conversational recency. Results are consumed directly from the run event stream with the existing transcript folder. The external functional model override takes precedence over the Profile's remembered model; absent both, the harness default applies. Only advertised ACP model controls are used, and functional execution does not write interactive Profile preferences. Custom commands receive no model injection. Unsupported model preferences produce a warning rather than guessed CLI flags. No backend failure triggers a switch to the other backend.

Missing/deleted/offline Profiles, Agent errors, invalid or incomplete output, and timeouts propagate to the existing `ENRICH_FAILED` diagnostic without marking enrichment capabilities complete. Metadata must include all requested non-empty fields with the expected types; unrequested fields are not applied. Frame titles must be non-empty, single-line, and at most 60 characters. A five-minute external task deadline requests cancellation; an interactive permission request aborts the background task rather than granting permission or waiting for unseen UI. These task instructions are behavioral guidance, not a sandbox. Agenetes already closes one-shot Jobs in the run generator's finalizer and awaits exact ACP process reclamation; this ownership is reused, not replaced with another host cleanup implementation.

On cancellation, `runFunctionalText` actively requests the same handle's cached close, including for a handle returned by late creation. Ordinary callers retain prompt cancellation and log late execution or cleanup failures. ACP close fences new session bootstrap and waits for pending bootstrap before removing the local session and reclaiming its exact process; bootstrap failure still attempts reclamation. This is not a hard deadline on startup or cleanup acknowledgement, and cancellation alone is not proof that a remote process has stopped.

`buildContentEnrichPrompt` requests conclusion-first summaries: actual facts, findings, decisions, or next steps rather than descriptions such as "This document describes." The existing string field may contain one or two short paragraphs or two to four flat Markdown bullet/numbered items, chosen according to the content, with important uncertainty preserved. The prompt requests at most 400 characters and excludes headings, media, HTML, tables, and code blocks; these are generation instructions, not new wire validation or truncation rules. Existing cached summaries are not automatically regenerated. PreviewCard renders the lightweight structure safely; text-only consumers continue to receive the same string contract.

Summary source input is bounded to 6,000 JavaScript string code units, including the truncation marker but excluding prompt instructions and the title hint. Short sources pass through unchanged; longer sources retain only their opening text, without splitting surrogate pairs at the truncation boundary. There is no heading recognition, section selection, or beginning/end stitching. Truncated input is explicitly identified as an opening excerpt and the model is instructed not to infer missing evidence or assume omitted caveats are absent. Findings later in the source can be omitted; this is a bounded card overview, not a full-document assessment. Label/keyword-only requests retain the existing 4,000-character prefix budget. Metadata still uses a single Utility Agent call. The budget bounds source characters, not tokenizer-specific tokens or the total prompt.

Image labeling uses the same global-default functional runner with text plus canonical image parts; Built-In uses the `imageLabel` role with its vision guard, while external uses ACP image input. It reuses chat image resolution, supported MIME types, and the 4 MB decoded-image cap without introducing a separate renderer or file-transfer channel. Missing pixels, unsupported image input, Agent errors, and invalid labels fail explicitly so enrichment remains retryable; there is no cross-backend fallback.
Agent `CREATE_NODES` and `MERGE_NODE_DATA` source imports preserve validated YouTube platform URLs verbatim only for `video` nodes, reusing the same ID parser as YouTube preprocessing. They never download the video page into an artifact, so embedding and cover extraction retain the platform source. Lookalike hosts and invalid video IDs do not receive this exception; other media and direct remote imports retain their existing download behavior. Content PUT already persists the supplied `src` verbatim without importing it; subsequent preprocessing uses that source.

Agent `CREATE_NODES` and `MERGE_NODE_DATA` also accept a PDF-only `coverUrl` under the agent command contract. The two entry points that validate against that contract, RFS `execute` and the built-in agent's canvas tool, pass `agentCovers` to the executor; only then does the executor boundary resolve a staged upload, artifact key, or HTTPS image into an existing raster artifact key (png, jpg, gif, webp, avif) before any `src` import, with `null` clearing the cover and restoring the first-page thumbnail. Other agent-origin callers of `executeOnServer`, such as the internal `/api/canvas/:id/execute` route, predate the contract and keep storing whatever cover string they send, on any node type, unfetched and unchecked. Under the contract, unlike a failed `src` import, a non-PDF target or an unavailable image rejects the whole request (`NodeCoverError`, HTTP 400) rather than storing a dangling cover. Availability is judged by the stored bytes, which must parse as one of those formats, not by the name: a `.png` URL can answer with an HTML page. Each distinct value is imported once per request, so several PDFs may share one staged upload. Staged cover uploads are reclaimed only after the executor has run the batch and every command was applied, so a request that throws or has a command rejected leaves them for the retry, and an upload named both as a cover and as a node `src` in one request is still there when sources are normalized. The cover stays structural node data, exactly as when a user sets it from a PDF selection.

## 3. Node profiles

Each `CanvasNodeType` declares `{ contentKind?, capabilities, watchFields }`. Selected profiles:

| Node           | Extract      | Enrich                                      | Persist | watchFields                 |
| -------------- | ------------ | ------------------------------------------- | ------- | --------------------------- |
| note / text    | text         | —                                           | ✅      | content, title, labelSource |
| web            | remote fetch | label + summary + keywords                  | ✅      | src, title, labelSource     |
| pdf            | text         | label                                       | ✅      | src, title, labelSource     |
| office         | text         | label + summary + keywords                  | ✅      | src, title, labelSource     |
| image          | —            | `generate_label` (vision)                   | ✅      | src, labelSource            |
| video          | cover JPEG   | —                                           | ✅      | src                         |
| frame          | —            | `generate_label` (summarise children)       | —       | childLabels, labelSource    |
| **question**   | —            | shared conversation naming (outside stages) | —       | content                     |
| sketch / audio | —            | —                                           | —       | —                           |

`question` declares only `resolve_input` + `build_patch`, watches `content`, and has no `persist_source` (not a knowledge source). Its pipeline entry calls `initializeQuestion(canvasId, nodeId, content, allowLLM)` and returns an empty patch and capability list: the shared service persists any accepted name through the canonical node writer and Canvas Sync, not through the preprocessing response. `allowPersistence=false` skips naming entirely; `allowLLM=false` or interactive mode permits fallback preparation without generation. Initialization checks the live Question content against the request before proceeding. `sketch` / `audio` only do `resolve_input` + `build_patch`. The `contentKind?` field (`web` / `pdf` / `office` / `note` / `text` / `image` / `video`) is just the Persist gate — set it and Stage 5 writes the node as a knowledge source; question has none. Registry: [profiles.ts](../../apps/server/src/modules/preprocessing/profiles.ts).

Each profile also declares **`bodyOwnership`** (`types.ts`): `'authored'` for user-editable bodies (`note` / `text`) → the Persist write is rev-CAS-guarded so a concurrent edit can't clobber the user's body; `'derived'` for pipeline-extracted, in-app read-only bodies (`web` / `pdf` / `office`) → no CAS (last-extraction-wins). The Persist stage reads this flag rather than hardcoding node types.

The ordinary `isLabelProtected` predicate is shared from `packages/shared/src/utils/node-label.ts`, with the existing preprocessing module re-exporting it so its callers retain their contract.

The YouTube loader resolves its Service provisioner only when fetching YouTube metadata/transcripts. Importing the shared loader registry does not initialize unrelated Service packages. Ordinary YouTube credential selection and requests are unchanged.

The ordinary `preprocess()` entry holds a Workspace lease for the whole request, and in-flight coalescing includes Workspace identity.

PDF preprocessing no longer generates automatic summaries or keywords, including forced runs. Extraction, local source snapshots, and label generation remain enabled; existing stored summaries/keywords remain readable. Office and Web enrichment are unchanged. Custom `properties` and `propertyDisplayKeys` are always authored: extraction retains their latest stored values and ignores same-named loader metadata. Content PUT applies no revision check to edits of these fields, on any node type: they are a per-key patch of the stored record ([what is versioned](./canvas-realtime-sync.md#what-is-versioned-and-what-is-not)). A PDF's owned Note is a separate node and record, reached through structural `noteNodeId`; PDF extraction never writes its body or revision. The Note uses ordinary Note preprocessing.

### Video covers

`getVideoFfmpegPath()` first selects the executable beside the server bundle at `media/<process.platform>-<process.arch>/ffmpeg` (`ffmpeg.exe` on Windows). A media directory with a missing target fails closed. Neither `PATH` nor `FFMPEG_BIN` selects the runtime executable, and runtime never downloads or compiles binaries. macOS development resolves only the same recipe-keyed source-build cache used by packaging; when absent, run `pnpm --dir apps/server media:prepare` with Xcode Command Line Tools installed. Other development hosts resolve `ffmpeg-static/package.json` without executing the package's environment-sensitive entry point.

macOS packaging builds **FFmpeg 7.1.3, LGPL-2.1-or-later**, from the unmodified [official source archive](https://ffmpeg.org/releases/ffmpeg-7.1.3.tar.xz), pinned to SHA-256 `f0bf043299db9e3caacb435a712fc541fbb07df613c4b893e8b77e67baf3adbe`. The pin was authenticated against the official detached signature using FFmpeg's published key, fingerprint `FCF986EA15E6E293A5644F10B4322F04D67658D8`; subsequent builds verify the pinned SHA-256 before extraction. Both arm64 and x64 are built using `/usr/bin/clang -arch ...` and `/usr/bin/make`, with a macOS 11 deployment target. The archive is cached once under `~/Library/Caches/huabu-ffmpeg/sources`; source/build staging and recipe-keyed binaries remain outside tracked sources. Cache reuse rechecks the executable hash, active configuration, architecture, license, compiler/SDK identity, and required components. The former nonfree macOS package binary is neither bundled nor selected in development.

The recipe disables GPL, nonfree, version3, external-library autodetection, networking, devices, hardware acceleration, assembly, documentation, debug information, ffplay, and ffprobe. It retains native video/image decoding, common-container demuxers, MJPEG encoding, image output, file/pipe protocols, and scale/format/null/fps/trim/thumbnail filters. The component audit requires fps, trim, and thumbnail; recipe revision 2 and the configure arguments select new cache directories without altering previous builds. MPEG-PS additionally needs the native MPEG elementary-stream probe. PNG explicitly enables Apple's system zlib; no downloaded codec library is linked. The dynamic dependency allowlist contains only Apple's libSystem, zlib, CoreFoundation, CoreVideo, and CoreMedia. Runtime retains the narrower container/protocol allowlists below; build-time image demuxers do not authorize image-sequence input through preprocessing.

The preparation command and server bundle hook audit Mach-O architecture, required/forbidden generated configuration, embedded active configure arguments/license, and dynamic dependencies, and execute `-L`/`-buildconf` for the host architecture. Cross-built targets use those static audits without requiring Rosetta; this is not a claim of cross-target runtime testing. Any nonfree flag, nonredistributable license report, unknown license, unexpected dependency, or mismatched cache fails the build rather than warning. Each macOS target carries LGPL text, upstream licensing notes, generated configuration, `BUILD.json` (toolchain, arguments, SHA-256, audit), and `SOURCES.txt`. The media folder also includes the exact full source tarball once, build scripts, and offline rebuild instructions, not merely a future source offer. Huabu invokes FFmpeg as a separate executable; these components are not relicensed under Huabu's MIT license. Preserve the source and notices in redistributed installers.

Windows/Linux retain pinned `ffmpeg-static@5.3.0` (release tag `b6.1.1`, which is not necessarily the executable version). Packaging preserves binary and package notices/source information, scans embedded configuration, and requires successful `-L`/`-buildconf` execution on a compatible host; GPL is allowed, nonfree and unknown licenses are rejected. These targets still require release owners to supply exact GPL corresponding source, including enabled libraries/build scripts, or a valid written offer; generic upstream links alone do not establish compliance. No Windows/Linux executable audit is implied by macOS validation.

Validation of recipe revision 2 used Apple clang 21.0.0 (`clang-2100.1.1.101`), SDK 26.5. Newly built executable SHA-256 values are arm64 `06a419fed325aa5f15fe253315cc12f7ac79914097bb9c0f4541740931648352` and x64 `0d15ac87ce4350b6590fa7d6f794f82508ebf22d7139719de0173ad323cc7b21`. These are not the former first-frame recipe's hashes; independent clean-build reproducibility has not been reverified for revision 2, and different toolchains are not promised identical hashes. The arm64 executable passed all 28 real decoder cases, including black/white openings followed by detail, partial-batch EOF, short/single-frame/unknown-duration fallback, white slides, all-black video, embedded JPEG/PNG priority, common codecs/containers, scaling, and playlist/corrupt-input rejection. Fixture encoding and pixel inspection use a separate development-only full FFmpeg. Both targets passed source-build and static audits; x64 runtime behavior remains untested on this arm64 host without Rosetta. Installer signing/notarization was not tested.

Video preprocessing uses the dedicated `extract_video_cover` capability, never transcript extraction, paid provider calls, or Enrich. The existing queue watches `src`; initial runs and source changes extract a cover, unchanged incremental snapshots run only structural capabilities, and `force=true` retries extraction. `allowPersistence=false` skips cover work entirely, including decoding, thumbnail fetches, and BlobStore writes.

Local sources must be Space-owned artifact references, not arbitrary filesystem paths. The pipeline materializes a `BlobLease` and releases it in `finally`. The decoder obtains its binary through the asynchronous `getVideoFfmpegPath()` provider and uses FFmpeg only (no ffprobe). Because FFmpeg 4.4 rejects `v:disp:attached_pic`, the decoder inspects FFmpeg's input stream listing for an attached-picture stream and decodes that index first; absent or undecodable embedded artwork falls back to `0:V:0`, whose uppercase `V` excludes attached pictures. JPEG output goes to `pipe:1`, fits within 1280 × 1280 without enlarging small inputs, and preserves aspect ratio. The existing `execFile` path retains `shell:false`, an 8 MiB output limit, and single-thread decoding/filtering/encoding. All attempts share one monotonic 30-second deadline starting before binary resolution: listing and individual artwork/first-frame attempts are capped at 10 seconds; sampling at 12 seconds while reserving 3 seconds for first-frame recovery. Remaining time caps every process timeout, with `SIGKILL` on timeout and no spawn after budget exhaustion. Input protocols remain restricted to `file,pipe`, and the common-container demuxer allowlist excludes HLS, concat, and image-sequence formats so playlists cannot become remote or local-file readers.

Ordinary video selection uses FFmpeg's existing histogram-based `thumbnail` strategy, not custom scoring, AI, or brightness rejection. Duration comes from the same input listing: known durations at most 1 second use the first frame directly; otherwise seek to `min(1 second, duration / 10)`, or 1 second when duration is unknown. Input `-t 6` and `trim=duration=6` bound the subsequent sampling window; `fps=2:round=near:eof_action=pass` samples it, then scale and `format=yuv420p` precede `trim=end_frame=12,thumbnail=n=12`. Thumbnail buffering therefore holds at most 12 scaled frames (about 28 MiB of pixel planes at 1280 × 1280, excluding decoder/filter overhead), not full-resolution frames. FFmpeg selects a representative frame from this early batch only, not uniformly across the whole video, and flushes incomplete batches at EOF. Empty output or sampling failure triggers one unseeked first-frame attempt within the original budget; there is no whole-video scoring pass. White slides and all-black videos remain valid; this heuristic does not guarantee a semantic highlight or avoid every blank opening.

YouTube sources reuse the loader's validated eleven-character ID parser, including watch, short-link, embed, Shorts, and live URLs. Cover fetching uses only fixed `https://i.ytimg.com/vi/<id>/maxresdefault.jpg` and `hqdefault.jpg` URLs, a 404-only fallback, `redirect:error`, a ten-second abort signal per request, JPEG checks, and an 8 MiB streamed-byte limit. No captions, provider metadata, credentials, or LLM are required. Other direct remote video sources are deliberately not fetched: they produce a nonfatal `VIDEO_COVER_FAILED` warning and remain playable through the normal frontend player.

JPEG bytes are stored through the Space's `BlobScope.put()` as a bare `cover_<uuid>.jpg` key under `.artifacts/` on Disk. The node stores only `coverUrl` and `coverSourceSrc`; the latter identifies the exact canonical `src` represented by the image. Both whole-canvas and single-node content reads restore matching references from the sidecar, excluding stale structural cover fields. A cache hit requires a matching persisted source and an existing cover blob, not merely a client-provided reference. Existing valid covers are not automatically migrated to thumbnail selection; an explicit regeneration (`force=true`) is required to replace them for the same source. Missing blobs are regenerated on the next preprocessing request; canvas loading alone does not backfill old videos. Extraction, thumbnail, or blob-write failures warn rather than fail video persistence, and clear obsolete cover fields. Existing valid covers are also cleared if a forced regeneration fails; another forced or initial-snapshot request retries.

Video persistence is a metadata-only branch of the existing `updateNode` coordinator: inside its atomic callback it requires an existing video sidecar and compares the live `src` with the requested source before **any** derived write. Legacy same-Space artifact API URLs and bare keys compare equivalently. A stale result or deleted sidecar causes no node write and no projected cover; identical empty bodies still refresh accepted cover metadata, while current labels, content, and unrelated metadata remain intact. Project emits only accepted persisted references, with explicit `null` pairs on the wire to clear obsolete client fields. The frontend preprocessing helper forwards these fields, checks the latest video source again, and applies a cover only when its source matches the accepted canonical source; the existing queue freshness guard remains authoritative for task state. Poster rendering additionally requires `coverSourceSrc === src`. Shared artifact-field traversal includes `coverSourceSrc`, so cross-Space cloning remaps source and cover provenance to the same cloned source key.

Blob writes precede source-fenced node persistence. A source change, deletion, or rejected node write can therefore leave an unreferenced cover blob; BlobScope has no per-key deletion, so such blobs remain until Space deletion. Source equality is not a request-generation ordering guarantee for simultaneous runs of the same source, and preprocessing does not introduce a general server freshness contract for other node types.

## 4. Triggers & state

### Who starts preprocessing

**The server starts it, where a write is committed.** A write that creates a node, or changes what a node's preprocessing reads, is followed by one run for that node — started by the server, once, whoever wrote (a person's page, an Agent, another service) and however many pages are open, including none. A page neither triggers this nor applies its result.

There are two commit points, and both ask the same question — did this node's preprocessing input change:

| Commit point                                          | Carries                                      | Selection                                                                       |
| ----------------------------------------------------- | -------------------------------------------- | ------------------------------------------------------------------------------- |
| The executor (`executeOnServer`): every command batch | A page's structural edits; every Agent write | `selectNodesToPreprocess()` compares the Space before and after the batch       |
| The node-content save (`PUT …/nodes/:id/content`)     | A title, source or body a page saves         | `selectAfterContentSave()` compares the stored record before and after the save |

Both live in [commit-trigger.ts](../../apps/server/src/modules/preprocessing/commit-trigger.ts). The input is `buildPreprocessSnapshot()` ([preprocess-snapshot.ts](../../packages/shared/src/utils/preprocess-snapshot.ts): title, `labelSource`, `content`, `src`; for a Frame its children's titles), compared field by field over the type's own `watchFields`. So a batch that only moves, restyles or re-places a node (a Grid cell, a paint or track key, an accent) starts nothing, and an image is not processed for a rename. A created node is always selected. Not selected:

- A `note` / `text` body. A page saves it as it is typed and asks when the editor is left (below); deriving a title from every intermediate body renamed the file again and again.
- A title that ends up automatic (`labelSource: 'auto'`) in a content save: that is what preprocessing produced, saved back, not a new input.
- A node an undo restored (`RESTORE_NODES`), except `pdf` and `video`: their extracted text and cover exist only in the record the deletion removed, so they are derived again. Every other node comes back complete, and deriving anything for it could only replace what the undo restored.
- Types whose pipeline does nothing (`sketch`, `spacePreview`, `fileReference`, `audio`).

The write paths do not depend on preprocessing: they call whatever [commit-follow-up.ts](../../apps/server/src/modules/canvas/commit-follow-up.ts) has installed, after the write is announced. `app.ts` installs `preprocessAfterWrites`; a server assembled without it (most unit tests) commits writes and starts nothing.

**Jobs** ([node-jobs.ts](../../apps/server/src/modules/preprocessing/node-jobs.ts)). One job per node. A node written again while its job runs is processed once more when the run ends, with the latest input and, as "before", what the pipeline last saw. The job sends the pipeline the previous input as `previousSnapshot`, so `buildPlan` reruns only the capabilities whose trigger fields changed (a rename does not re-extract or re-summarise). A job runs in the call that committed the write, so the Utility Agent, credentials and network restriction it uses are that caller's: the member whose page or whose Agent run made the change, and the deployment's for a machine credential.

**Result and status.** The pipeline persists the extracted body as before. What it used to return for the requesting page to save — a suggested title with `labelSource: 'auto'` (dropped when a person or an Agent has named the node meanwhile), a canonical `src`, summary and keywords — the job writes to the node record itself (`updateNode`) and announces with `invalidate { nodeIds }`, which every page handles as it handles another page's content save: it fetches the node, with no undo entry. A video's cover is stored in the node record by the pipeline; the job also sends it through the executor (`MERGE_NODE_DATA`), so that open pages receive it in an `update` without reloading. Status travels as `preprocess { nodeId, status }` events on the Canvas Sync stream: `pending` when a run starts, then `done` or `error`. A page shows them as the node's ingestion state and forgets a pending state when the stream reconnects, since the end may have been missed. Nothing is kept for a page that is not listening.

Running jobs are awaited when the server closes. They are not durable: a run cut off by a crash is not resumed, and the next change to the node's input starts a fresh one.

**Record fields only the server derives.** Some fields of a node record are produced by preprocessing and read only by the server: a video's `coverUrl` / `coverSourceSrc`, a web page's `mhtmlArtifact`, loader metadata. No page holds them, so the node a command batch hands back does not either. When the executor stores the record of a node a batch changed, it takes what the node carries and keeps every other field of the stored record (`recordToStore` in [canvas-executor.ts](../../apps/server/src/modules/canvas/canvas-executor.ts)); a record rebuilt from the node alone dropped the cover or the saved snapshot whenever such a node was recoloured or renamed. A node re-created under the same id starts without them.

### What a page tells the server

A page starts no preprocessing and applies no result. One thing only a page knows, and it says so on a request it makes anyway:

- **An editor was left** (`note` / `text`). Their title derives from the first heading or line, so deriving it from each body saved while typing churned the `.md` filename (`Note 1.md` → `H.md` → `He.md` → …). The body keeps saving on the content queue's cadence; when the editor is left, `endNodeEditing` ([canvasStore.ts](../../apps/web/src/store/canvasStore.ts)) marks the node in [nodeContentQueue.ts](../../apps/web/src/store/canvasStore/save/nodeContentQueue.ts) (`markEditingEnded`), and the node's next content save carries `editingEnded: true`. A save is sent at once for it, even when nothing of the node is unsaved. The server then derives the title from the body it holds (`selectAfterContentSave`).

  The mark rides on the node's content saves, so it has their order for free: it waits for a restore to be acknowledged, for a conflict to be answered and for a failed save to be retried, goes out with the unload keepalive, and is dropped when a save that carried it succeeds. Canvas store subscriptions decide when an editor counts as left: they compare active Preview Workspace node targets before and after topology changes, including programmatic conversation opening, transient replacement, closing and split-group moves; collapsing the right panel and page lifecycle preparation leave every active preview editor. Ordinary DOM blur, toolbar interactions, group focus and reordering a still-visible editor do not. Inline `text` uses `TextNode`'s blur handler.

Two things a page used to ask for are gone or moved. A returning Agent Node's conversation is named by the association route that re-associates it (`agentNodeRestored`). An empty title is no longer retried whenever a Space is opened: every created node is preprocessed by the server, and a run that failed is retried by the next change to the node's input (see §6).

`POST …/nodes/:id/preprocess` still exists and runs the pipeline for a caller that supplies a snapshot; no page calls it.

- `contentMissing` is a write barrier, not only a rendering hint. GET hydration marks every Markdown-backed node type, including Frame and Sketch, when its `.md` is absent. `nodeContentQueue` refuses to build a content PUT for it, with or without an editor having been left. The preprocess route also rejects an absent sidecar before dispatch, while the Persist stage atomically requires an existing record so an already-running extraction cannot recreate the file after external deletion. Extraction-failure placeholders may update an existing sidecar but never create one. Opening, closing, switching an expanded editor, renaming, or preprocessing therefore cannot silently recreate a frontmatter-only `nodes/<nodeId>.md`. Every missing content/artifact node uses the shared `MissingFileBanner`; the component fills the node and selects its compact row or full-card layout from its own container height, while preserving the same border, copy, and Remove action. Missing `note` and `text` nodes replace their editor with this non-editable placeholder, while missing Frame and Sketch sidecars preserve structural geometry but disable their sidecar-writing controls. The Text placeholder is constrained to the same `useTextAutoSize` body box instead of sizing the React Flow node from its warning UI; Text height remains content-owned and is not persisted in `space.json`, so after the sidecar content is lost its prior content-derived height cannot be reconstructed.
- `node_inserted` / `node_updated` carry a snapshot; dispatcher diffs against the profile's `watchFields` to plan the minimum stages.
- Label policy: ordinary Enrich may propose a label, but Project includes it only when the request label is not a non-empty `user`/`agent` label. Because a run can be under way when the user renames a node, the job re-reads the stored record when it writes the result and leaves a title that is user/agent-owned by then; the other fields are still written. The planner skips `generate_label` for protected labels. Questions bypass this path entirely, and Project explicitly excludes their automatic labels as a defensive boundary.
- The server enforces ordinary automatic-label protection again at commit: the Canvas executor removes only automatic `label`/`labelSource` fields over a currently protected label, and the content PUT resolves automatic labels against the latest sidecar under the shared Canvas mutex. Question naming instead uses the shared conversation-title policy and its node adapter: `label` is the only title value, `conversationTitleSource` is protected provenance, and accepted automatic names retain `labelSource: 'auto'`. The service rechecks current ownership, content, and label protection before an asynchronous result can write. Conversion transfers authority to the node, allowing eligible late generation and ACP updates to continue without maintaining two competing titles. Undefined generation or provider failure permits a later turn/initialize retry; see [shared conversation naming](./agent-architecture.md#panel-conversation-titles).
- Error recovery: failed extraction throws `EXTRACT_FAILED`; Persist is canvas-local (keyed by `nodeId`, written to `nodes/<nodeId>.md`) and may store placeholder metadata only when that sidecar still exists.

### Responsibility boundary

| Owner              | Responsibility                                                                                                                  | Does not own                                                 |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| Server             | Decide after every committed write whether a node needs preprocessing; run one job per node; store the result; announce status. | When a person is done editing a body.                        |
| Editors            | Say that an editor was left (`endNodeEditing`).                                                                                 | Requests, timers, results.                                   |
| `nodeContentQueue` | Save node content in order, across restores, conflicts and failures; carry the editing-ended mark on those saves.               | Whether preprocessing is needed, and anything of its result. |

## 6. Not yet done

- Server-started runs are not durable and not announced to late pages: a page that loads while a run is under way shows no pending state, and a run lost to a crash is not resumed. There is no retry for a failed run other than the next change to the node's input.
- A run that failed is not retried on its own. The page-side retry that asked again for every empty title whenever a Space was opened was removed: it asked once per open page and again on every load, including for nodes that can never get a title.
- The run started by an editing-ended save has no previous input and so runs the whole profile; for `note` / `text` that is title derivation only.
- `applyDeltasOnServer` writes (Review revert, Agent Node projections, cross-Space moves) do not pass through a commit point that starts preprocessing.
- The web queue fences superseded task projections and status callbacks, but does not cancel or version-check general server persistence. Video covers have the source-equality fence described above; other derived-content writes can still race live-node history changes, and DELETE-before-resurrection ordering does not apply to nodes that remain present. Request identity is client-local, not a cross-tab/server freshness contract. Completed preprocessing is not automatically recomputed for every history change; this reconciliation resumes unfinished work rather than introducing a general derived-data invalidation system.
- No per-canvas token budget; no batch enrichment (nodes processed one at a time).
