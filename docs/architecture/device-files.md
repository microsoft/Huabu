# Connected-device File Explorer

The Files mode in the left Canvas sidebar browses files on an explicitly selected connected Agentlet. The working-directory popover beside Chat's Profile selector offers **Browse files** for its effective device and directory without editing either. Realized conversations use the frozen execution device and cwd, not the current Profile template. Legacy executions without a known frozen device cannot guess a replacement.

## Transport and ownership

```text
Files sidebar / file-reference Preview
  -> owner-only POST /api/acp/files
  -> private queued ACP Job on the exact Agentlet
  -> bundled proxy harness, session/prompt
  -> native read-only filesystem operations
```

Agentlet bundles the deterministic `proxy` ACP executable beside its daemon. Discovery provisions one automatic Profile per device with `harnessId: "proxy"` and `visible: false`. Missing `visible` means visible for existing Profiles. Normal Profile lists, selectors and absent-only Utility defaults exclude hidden Profiles; hiding is presentation, not an authorization boundary. Manual creation reserves the proxy harness. Discovery and launch reuse existing Agentlet messages and the ACP relay; there is no new filesystem WSS method, shell command dispatcher, downloaded runtime or model call.

The Server lazily maintains at most four device sessions, with at most eight queued operations per device and FIFO execution within each session. These are private Jobs with no Chat node, durable conversation transcript, RFS environment or conversational recency update. Their neutral Profile cwd does not change with browsing. A cold request has a 60-second deadline and a warm request 10 seconds. Idle sessions retire after 60 seconds, checked every 15 seconds. Disconnect, reconnect, failure and shutdown retire the old generation, shut down the client and reclaim its Agentlet process. Late startup retains admission ownership until it settles and can be reclaimed; failed reclamation is explicit and retryable rather than admitting replacement processes silently.

## Command contract

The proxy advertises its read-only filesystem contract in its ACP `initialize` response as `agentCapabilities._meta["com.microsoft.agentlet/filesystem"] = { version: 1, binaryRead: true }`. The extension key, capability value, `supportsFsProtocol`, and `supportsFsBinaryRead` validators are canonical exports from `@agentlet/protocol`. The Server validates `supportsFsProtocol` from the current client's initialization result before sending any filesystem prompt; missing, malformed or unsupported versions fail explicitly with `files_proxy_incompatible` and an Agentlet-update message. Legacy v1 Agentlets (`{ version: 1 }` without `binaryRead: true`) remain valid for `fs-list` and `fs-read`, while `fs-read-bytes` checks `supportsFsBinaryRead` and fails explicitly with `files_proxy_incompatible` without tearing down the healthy v1 proxy session. Client request aborts propagate `AbortSignal` cancellation to queued and active proxy turns without retiring a healthy session. A saved Profile or command catalogue is not capability proof. Existing Agentlet bootstrap metadata carries the complete initialization response before the session becomes usable, so there is no second capability handshake, command-notification wait or polling step. The proxy retains `available_commands_update` for compatibility with older Servers, but its arrival or absence does not gate Files on the new Server.

A prompt contains exactly one text block: `/COMMAND ` followed by one strict JSON object. Unknown commands and fields are rejected. Each call is self-contained; ACP session reuse is an optimization, not filesystem command state. There are no root IDs, open/close operations, retained file handles or per-browser authorization roots.

| Command         | Input                                                                        | Result                                                                                                     |
| --------------- | ---------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `fs-list`       | Absolute `path`; optional `cursor`, `limit` (1–100), `showHidden`            | Canonical `path`, `parentPath`, bounded `entries` (`name`, absolute `path`, `kind`), optional `nextCursor` |
| `fs-read`       | Absolute `path`; optional `cursor`, `limitBytes` (4–65,536)                  | `path`, `encoding: "utf-8"`, source `text`, `byteLength`, `size`, `contentVersion`, optional `nextCursor`  |
| `fs-read-bytes` | Absolute `path`; optional `cursor`, `limitBytes` (1–262,144), `maxSizeBytes` | `path`, `encoding: "base64"`, Base64 `data`, `byteLength`, `size`, `contentVersion`, optional `nextCursor` |

The response is one JSON document: `{ version: 1, operation, ok: true, result }` or `{ version: 1, operation, ok: false, error: { code, message } }`. The Server assembles bounded text notifications and accepts a result only after successful `end_turn`, response schema validation and matching operation. ACP completion alone is not filesystem success. Permission requests are rejected. Raw file output is not written to runtime diagnostics or conversation history; HTTP results use `Cache-Control: no-store`.

Paths are native absolute paths on the selected Agentlet, not the Huabu Server or browser. The process OS account is the authority: all readable paths are accessible, normal symlinks are followed, and no privilege elevation or project-root confinement is added. Only directory listing, stable-sized regular UTF-8 text reads, and bounded regular-file Base64 chunk reads (`fs-read-bytes`, used for read-only PDF preview) are implemented. Binary/invalid text on `fs-read`, files exceeding `maxSizeBytes` (`file_too_large`, HTTP 413), special or generated files without stable size metadata, inaccessible paths and malformed requests fail explicitly. The proxy uses nonblocking read-only opens to avoid blocking on a substituted FIFO.

List cursors encode the canonical directory, hidden-file option and last name. Pages are best-effort under directory mutation, not snapshots; the UI deduplicates entries. Scans are capped at 20,000 entries. Read cursors encode cursor encoding (`utf-8` vs `base64`), path, byte offset and a version derived from filesystem identity, size and timestamps; cursors cannot be reused across `fs-read` and `fs-read-bytes`. Text reads preserve UTF-8 boundaries, and both text and binary reads reject changes between or during chunks; they do not retain file descriptors across calls. Responses are capped at 524,288 serialized bytes. Cursors are continuation positions, not secrets or authorization grants.

## Canvas and Preview

Files uses existing Common controls and `react-virtuoso` for a lazy expandable directory disclosure list. It loads directories on demand, supports hidden-file filtering and pagination, and caps a mounted tree at 2,000 entries and 32 nested levels. There is no watcher, polling or rename tracking. Layers remains the other sidebar mode, and Canvas search switches back to Layers.

[`DeviceFileTree`](../../apps/web/src/components/Panels/deviceFileTree.ts) owns every listing request, outside React. At most four run at once, because the Server rejects a device's ninth pending filesystem request and file Previews read from the same device. The listing on screen stays until its replacement arrives, so the list never blanks. A folder row follows its click at once; the reply fills it in without reopening one closed meanwhile. Moving to another directory lists only that directory and reuses the listings of folders already open; Refresh and a change of the hidden-file setting re-list the root and every open folder, and a Refresh under way is left to finish rather than restarted. A next page is applied only while the listing it continues is still on screen.

Browsing needs no typed path. With nothing open, Files starts on the device the Space browsed last, else the Server's own machine, else the first connected device, at the directory last opened there or the device root (`/`, or `C:\` on Windows). A remembered directory that can no longer be listed falls back to the root. The last directory per Space and device lives in the persisted panel store, capped at 100 entries; their order records which device was browsed last. The header is the current folder's name: its menu shows the full path (click to copy), opens the parent folder, takes a typed path, refreshes and toggles hidden files. The device is a separate control, labelled only when more than one is connected, and the native folder picker appears for the Server's own machine. A folder's menu offers Open here, which makes it the root.

Each directory displays its currently loaded folders before all other entries, preserving the received name order within each group. This frontend-only ordering operates on a copy of the merged entries before expanding children; it does not filter entries, alter cached pages or change pagination cursors. Newly loaded folders move above files, expanded children stay with their parent, and Load more remains last within that directory. Unresolved symlinks and other unsupported entries remain visible. Folders not yet loaded are not fetched automatically to complete the ordering.

File and directory rows replace the browser context menu with Copy name, Copy relative path and Copy full path. Relative paths follow the displayed hierarchy from the currently opened root, preserving browsed symlink names and the source device's path separator; full paths copy the entry's absolute device path verbatim. These actions copy metadata only, reuse Common DropdownMenu and the existing clipboard fallback, and report clipboard failures visibly. An actions button appears on row hover or keyboard focus (and remains visible on touch) and opens the same menu, including with Shift+F10 or the Context Menu key. File menus also offer Add if needed and open, and Add to Space; folder menus offer Open here; there is no inline plus button. The path input, shown while a path is being typed, retains its native editing menu. Rows share the sidebar row styles with the Layers tree; folders show only a disclosure arrow and files a type icon, and one indent level equals the icon slot plus its gap. Up/Down/Home/End navigation scrolls logical rows into view before moving focus through the virtualized list.

Clicking a file, or activating its button with Enter/Space, opens it in the Preview workspace's reusable slot through a `file` Preview target that carries the Agentlet ID and absolute path. Browsing is node-free: looking at a file does not change the Space, and works in read-only Spaces. The row of the file on show is highlighted. Such a Preview has no node, so its header offers Add to Space, and a comment captured from it records no node ID.

Choosing Add if needed and open instead reuses a file-reference node in the current Space with the exact same Agentlet ID and absolute path. Existing open matches take precedence (most recently active first); otherwise the first matching node in Canvas order is reused. Device names, filename extensions, path case and symlink aliases do not change this identity. If no match exists, the ordinary Canvas command creates a visible, undoable reference before opening a permanent node-preview tab. That command is the store's `addNode`: like every structural gesture it is sent through the page's send queue to `POST /api/canvas/:canvasId/execute`, and other open pages receive the node in the `update` event ([realtime sync](./canvas-realtime-sync.md)); nothing is created while the Space is still loading. Failed creation does not open a dangling tab; repeated activation observes the synchronously created node and reuses it. Read-only Spaces may open existing references but cannot create new ones. The helper rechecks current Space and write access at activation time. Explicit Add to Space and drag-to-Canvas still create references deliberately, including additional references to the same file.

Adding or dragging a file uses existing Canvas commands to create a `fileReference` node. Structural data stores only `{ agentletId, path, deviceName? }` under `data.fileReference`, plus ordinary presentation fields. The label uses a frontmatter-only node sidecar. Content/source mutation endpoints reject source bytes on these nodes. Duplication and bundle export preserve inert references, not external file contents. Loading a Canvas or processing/searching its nodes does not read remote files or import them into artifacts.

Opening a file-reference Preview reads supported UTF-8 text into component-local state. The view reuses read-only CodeMirror and the official `@codemirror/language-data` catalogue to load only the matching language, with a plain-text fallback for unknown extensions. Highlighting installs through a CodeMirror compartment without replacing the editor or its selection; failed language loading reports an error while retaining readable source. Device-native basenames support both Windows and POSIX separators. `.tex` remains source and is never compiled. Manual refresh restarts from the path, including a replacement made by atomic save. Read more continues up to a 256 KiB display cap; stale content and offline devices remain explicit errors until retry. No edit, download-as-import, automatic AI ingestion, shell execution or automatic reference repair is provided.

Complete `.md`, `.markdown`, `.mdown` and `.mkd` files additionally offer Reading and Source modes. Reading splits a closed leading `---` YAML frontmatter block into a collapsible read-only Frontmatter section above the body instead of passing the fences to CommonMark or interpreting file metadata as Space node properties, while unterminated opening fences, later horizontal rules and fenced code blocks remain part of the body; it lazily reuses Milkdown for single-file headings, lists, tables and code blocks, and code-fence languages use its existing lazy language support. The opt-in single-file policy renders links as text and images as bracketed alt text, without assigning image sources or resolving local, artifact, remote or data URLs. Raw HTML is not injected as executable DOM. No file-relative navigation, external link navigation, image fetching, imports or additional device reads are triggered by rendering. Other Note and Chat surfaces keep their existing resource behavior. Partial files remain in Source until the user finishes loading within the display cap and explicitly chooses Reading. Source mode retains precise excerpt and Comment actions; Reading supports ordinary text copying and explains how to return to Source for those actions. Rendering failures display an error and return to Source.

`.pdf` paths (both node-free `file` Preview targets from File Explorer and `fileReference` nodes) lazily mount `DevicePdfPreview` instead of reading UTF-8 text. The web client reads bounded 256 KiB Base64 chunks through `fs-read-bytes` up to a 32 MiB (`33,554,432`-byte) cap, verifies a `%PDF-` header within the first 1024 bytes on the first chunk, checks `contentVersion` and `size` across chunks, and renders an ephemeral in-memory `Blob` through the shared `react-pdf` page virtualization and zoom primitives (`usePdfDocumentLifecycle`, `usePdfZoom`, `PDFZoomControls`, `PDFPageWithOverlay`) with annotation links disabled and native text selection enabled. Browsing a PDF never uploads Space artifacts, creates Canvas nodes, or invokes AI; clicking Add to Space in a node-free PDF preview creates a `fileReference` node preserving the exact `{ agentletId, path, deviceName? }` identity rather than importing a `pdf` artifact node. Node-only PDF mutations (persistent highlights, area-capture uploads, cover images, owned notes, node properties, and drag-excerpt handles) are excluded. Password-protected PDFs intercept `onPassword` and `PasswordException` to fail explicitly without browser password prompts; oversized, changed, missing, permission-denied, offline, corrupt, and legacy-Agentlet errors surface distinct status alerts, and switching files or unmounting aborts in-flight chunk reads and releases the `pdf.js` document task.

Production builds keep optional language grammars in separate `syntax-*` chunks. The Markdown editor's existing static HTML/JavaScript/CSS dependencies remain shared, while Python, C/C++, Rust, JSON and other optional languages are loaded on demand. See the [bundle boundary](./desktop-startup.md#3-the-first-screen-bundle-boundary).

A single nonempty contiguous text selection offers the shared Copy, Add as note and Comment actions in the same order as Chat and Note. Copy puts exactly the selected source text on the clipboard, with explicit retryable failure feedback. Add as note creates a Space Note containing the selected source text with `user-excerpt` provenance pointing to the File Reference node; it never writes back to the file. Both actions clear the selection after success. The active-line background stays below CodeMirror's selection layer, so selecting part of a wrapped line remains visible. Comment uses the existing Preview Comment editor and existing-conversation destination picker. Explicit staging shares only the captured quote and up to 40 UTF-16 positions of neighboring loaded text per side, not the full file or an implicit attachment. The structured file source freezes Space/reference-node ID, Agentlet ID, canonical returned path, `contentVersion`, UTF-16 selection offsets, loaded document length and completeness. Offsets address CodeMirror's line-ending-normalized text, not UTF-8 byte positions. `contentVersion` identifies observed filesystem state, not a content hash or a retained historical file; the source device may differ from the receiving Agent's execution device. Metadata appears in the escaped model reference template, not editable comment text.

CodeMirror's model owns capture even when selected lines are virtualized. New capture is unavailable during loading or a read error; an already opened Comment retains its original labeled snapshot across refresh/read-more/failure. Switching reference identity closes that editor rather than retargeting it. Capture never reads more bytes, edits/imports the file, creates an Agent, submits a turn or navigates to a hidden conversation. Hidden drafts reuse the explicit View input notification described in [Preview Workspace](./preview-workspace.md). Chat, Note, Ink and other Preview types retain their existing behavior.

File comments reuse the shared visit-scoped destination policy: current picker choice, last successfully added non-Chat comment target, last user-previewed Agent, then the server's recent accepted conversation. Canvas selection is not destination intent. Opening another file or remounting its preview preserves the visit's last staged target, while an open form remains stable through background activity. Missing owners, pending forks and changed Workspace/Space scope block staging instead of silently choosing another Agent. Temporary-Chat history requires an explicit existing-Agent choice here; File does not create or implicitly realize conversations.
