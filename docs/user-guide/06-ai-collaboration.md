# 06 · 人机协作

Huabu 的 AI 与你**共享同一块画布**。它能读到画布的整体语境，也能在你身边动手 —— 你不需要把自己工作的来龙去脉手动塞进对话框。

本章覆盖三种协作入口：

- **Chat 面板** —— Ask / Operate 两种模式
- **Question 节点** —— 把 Ask 直接放到画布上（详见 [04 · 节点详解](./04-nodes.md#question问题节点)）
- **Intent 系统** —— `Ctrl/Cmd+I` 让 AI 推荐"接下来做什么"（详见 [07 · 意图与自动布局](./07-intent-and-auto-layout.md)）

---

## 心智模型

**画布是共享记忆**。你看到的就是 AI 看到的；AI 写出来的也直接落到画布上。具体来说：

- AI 在每次回复时都能拿到画布概览（节点列表、Frame 结构、近期操作）
- 你**选中**的节点会被作为"焦点"，其完整内容（不截断）一并提供给 AI
- 已入库的内容（[Sources](./05-sources-and-knowledge.md)）AI 可主动检索

---

## Chat 面板

入口：画布右侧的 Chat 面板。输入框左侧的模式选择器可在 **Ask** 和 **Operate** 之间切换；同一个对话线程可以来回切换模式。

### Ask 模式

适合：自由问答、解释、综述、轻量的"创建一个 Note 把答案写下来"。

特点：

- AI 流式输出文字回答到对话气泡
- 按需调用工具（见下文工具表）
- AI 不会主动批量改画布；如果它要创建节点，也是边输出边创建，仍可用 `Ctrl/Cmd+Z` 单步撤销

可用工具：

| 工具              | 作用                                               |
| ----------------- | -------------------------------------------------- |
| `web_search`      | 通过 Tavily 搜索互联网                             |
| `get_node_detail` | 拉取某个节点的完整内容（用于深入读选中之外的节点） |
| `read_source`     | 按 sourceId 读取入库内容                           |

### Operate 模式

适合：批量整理、精确画布编辑、把意图变成一组操作。

特点：

- 你用自然语言描述想要的画布变更
- AI 调用 `canvas_commands` 一次性产出一组结构化操作（创建 / 移动 / 连线 / 分组 / 修改等）
- 操作应用后画布旁会显示**变更清单**：可整体撤销、整体保留，或逐条审查
- 复杂任务时 AI 可能调用 `use_skill` 加载 step-by-step 指引

可用工具（在 Ask 工具集基础上扩展）：

| 工具               | 作用                                                    |
| ------------------ | ------------------------------------------------------- |
| `web_search`       | 同上                                                    |
| `get_canvas_state` | 拉取整张画布的概览（节点 / 连线 / Frame）               |
| `get_node_detail`  | 拉取单个节点完整内容                                    |
| `canvas_commands`  | 应用一组结构化的画布命令（创建 / 移动 / 连线 / 分组 …） |
| `read_source`      | 读取入库内容                                            |
| `search_knowledge` | 在工作区 Sources 中按关键词检索                         |
| `ingest_content`   | 让某个节点立刻入库（用于 AI 决定先把材料入库再综合）    |
| `use_skill`        | 加载某个技能（skill）的详细指引                         |

### 两种模式的选用建议

| 你想做的事                     | 选哪个               |
| ------------------------------ | -------------------- |
| 问问题、要解释、要总结         | **Ask**              |
| 让 AI 在画布上批量整理 / 重排  | **Operate**          |
| 让 AI 写一段笔记并放到画布上   | 任一都可，Ask 更轻量 |
| 不希望被改动画布，只想得到答案 | **Ask**              |

## AI 看到了什么（上下文构成）

每次发送消息时，后端会构造下面这些信息一起送给 LLM：

| 上下文部分   | 说明                                              |
| ------------ | ------------------------------------------------- |
| 节点摘要     | 所有节点的类型、标题、内容片段                    |
| Frame 结构   | 节点的分组与父子关系                              |
| 选中节点全文 | 当前选中节点的**完整内容**（不截断）              |
| 近期操作     | 最近的画布操作历史（创建 / 删除 / 连线 / 移动等） |
| 入库内容     | 选中节点对应的 Source 全文（如已入库）            |
| 附件         | 你从 PDF 选区"发送到 Chat"的图片或文字            |

> 💡 想让 AI 聚焦：**先选中相关节点，再发问**。

## 对话历史与多线程

每张画布都有自己独立的对话历史，按线程（thread）分文件存储：

- 路径：`<workspace>/.history/<canvasId>/<threadId>.json`
- 关闭并重新打开应用后历史仍在
- 不同主题建议开新线程，避免上下文混杂

> 📌 旧文档曾提及 LangGraph checkpoints，已不再使用 —— 现在的实现是自研 agent loop（[agent.service.ts](../../apps/server/src/modules/agent/agent.service.ts)）+ pi-ai 作为 LLM 网关。

---

## 从对话到画布

- AI 在对话中创建的节点会带 `chat` 来源标记，自动布局时会跟同线程节点聚集（详见 [07 · 意图与自动布局](./07-intent-and-auto-layout.md#隐式语义边)）
- 你可以**把对话消息中的内容直接拖到画布**，自动创建一个 Note
- PDF 选区可以一键作为附件发送给 Chat

---

## 注意事项

- 回复质量取决于你配置的 LLM 提供商和模型，详见 [09 · 设置与 LLM](./09-settings-and-llm.md)
- 复杂的 Operate 指令（"整理整个画布"）可能需要十几秒到几十秒
- Ask 模式下 AI 的画布变更可用 `Ctrl/Cmd+Z` 单步撤销；Operate 模式下使用变更清单整体管理
